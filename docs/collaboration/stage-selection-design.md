# 스테이지 선택 화면 기획서

작성일: 2026-11-19

상태: **Main 씬에 구현**. 스테이지 순서와 비용은 테스트용 임시안이다.

## 1. 목표와 현재 구조

월드 화면에서 실제 전투 맵을 미리 보고, 특성 포인트로 스테이지를 해금·선택한 뒤 기존 사냥 버튼으로 전투를 시작한다. 사용자 레벨로 얻는 특성 포인트는 특성 카드 공개와 스테이지 해금이 함께 사용한다.

[Main.unity](../../Assets/CursorHunter/App/Scenes/Main.unity)의 `UICanvas/World_Canvas`에서 스테이지를 구매·선택한다. 씬의 `IsometricMaps`에는 숲·사막·겨울·해변·우주·공사장 맵이 배치되어 있다. 일반전과 보스전 입장 때 선택한 맵과 전장 경계를 연결한다. 각 맵은 [아이소메트릭 맵 안내](../../Assets/CursorHunter/Combat/Prefabs/Maps/README.md)의 프리팹을 사용한다.

기존 필드 5단계는 사용자 레벨에 따른 자동 해금과 별도 선택값을 사용한다. **새 스테이지의 구매 기록은 처음부터 생성하며 기존 필드 해금·선택 기록을 구매 기록으로 이관하지 않는다.** 새 스테이지 전투에서는 기존 필드 단계와 그 단계의 젬스톤·경험치 보너스를 사용하지 않는다. 기존 경험치·특성 카드·포인트 등 다른 진행 데이터와 특성 카드 효과는 유지한다.

## 2. 스테이지 순서와 해금 비용

순서와 비용은 다음 임시안을 사용한다. 숲은 처음부터 해금·선택되어 있으며 비용이 없다. 나머지는 특성 포인트를 사용해 한 번씩 구매한다.

| 순서 | 스테이지 | 실제 맵 프리팹 | 해금 비용 | 몬스터 경험치 배율 | 몬스터 체력 배율 |
|---:|---|---|---:|---:|---:|
| 1 | 숲 | `IsometricGrassland` | 기본 제공 | 1.00배 | 1.00배 |
| 2 | 사막 | `IsometricDesert` | 1포인트 | 1.00배 | 1.00배 |
| 3 | 겨울 | `IsometricWinter` | 1포인트 | 1.00배 | 1.00배 |
| 4 | 해변 | `IsometricBeach` | 2포인트 | 1.00배 | 1.00배 |
| 5 | 우주 | `IsometricSpace` | 2포인트 | 1.00배 | 1.00배 |
| 6 | 공사장 | `IsometricConstruction` | 3포인트 | 1.00배 | 1.00배 |

두 배율은 우선 모든 스테이지에서 1.00배로 시작하며 나중에 스테이지별로 조정한다. **일반 사냥의 일반 몬스터에만** 적용하고 보스 전투와 특성 카드로 등장하는 보물상자에는 적용하지 않는다. 보스 전투에서는 향후 추가되는 스테이지 특성도 적용하지 않는다.

일반 몬스터의 체력은 전투에 전달할 몬스터 체력에 스테이지 체력 배율을 곱한 뒤 **올림**해 정수로 적용한다. 예를 들어 적용 전 체력 15에 1.10배를 적용하면 17이다. 체력은 최소 1을 유지하고, 유효하지 않은 배율이나 정수 범위를 넘는 결과는 전투 시작 전에 거부한다.

일반 몬스터의 경험치는 기존 몬스터 경험치에 스테이지 경험치 배율을 곱한다. 경험치 증가 특성 카드를 보유한 경우에는 그 효과도 기존 규칙대로 곱해 적용한다. 기존 필드 단계의 경험치 배율은 사용하지 않는다. 소수점 경험치는 기존처럼 전투 중 누적해 정수로 지급하며, 배율이 1.00보다 작아도 실제 수치에 반영한다. 젬스톤은 기존 필드 단계 보너스나 새 스테이지 배율 없이 기존 몬스터 보상과 별도의 특성 효과를 따른다.

해금하려면 **바로 앞 스테이지가 해금되어 있고 해당 비용 이상의 포인트를 보유**해야 한다. 별도 레벨 제한은 추가하지 않는 안이며, 조건과 비용은 플레이 테스트 후 조정할 수 있게 데이터로 관리한다. 전체 추가 스테이지 비용은 임시안 기준 9포인트다.

현재 레벨 상한은 25이고 레벨업으로 획득하는 포인트는 총 24개다. 현재 특성 카드 4종의 공개 비용 합계 10포인트와 스테이지 비용 9포인트를 모두 쓰면 5포인트가 남는다. 이는 현재 카드 수·레벨 상한과 해당 임시 비용만을 기준으로 한 계산이며, 새 카드나 추가 스테이지의 경제 설계는 별도 검토한다. 카드의 기존 공개 비용과 선택 규칙은 [특성 카드 설계서](trait-card-design.md)를 따른다.

특성 카드와 스테이지는 장기적으로 모두 획득할 수 있도록 한다. 초반에는 플레이어가 포인트를 어디에 먼저 쓸지 선택한다. 현재 콘텐츠 기준으로는 레벨 상한 25와 레벨업당 1포인트 지급을 유지하고, 추후 콘텐츠 추가로 포인트가 부족해지면 필요한 총량을 고려해 레벨 상한을 확장한다. 상한 확장 시 기존 만렙 플레이어의 누적 경험치와 포인트 지급을 빠뜨리거나 중복 지급하지 않도록 처리한다.

## 3. 화면 구성과 스타일

기준 해상도는 기존 `UICanvas`의 1920×1080이다. 화면 비율에 따라 여백과 스크롤 영역을 조정하되, 한 번에 약 3개 스테이지가 보이도록 한다.

```text
[연구] [유물] [특성] [월드 ●]

[특성 포인트 아이콘  보유량]       선택한 스테이지: 숲

           ⓘ                     🔒                     🔒
     실제 숲 맵              실제 사막 맵             실제 겨울 맵
                            [책 아이콘 1]
        숲                     ???                    ???
        ☑──────────────────────○──────────────────────○

[뒤로] [홈] [도움말]                                [보스] [사냥]
```

- 배경은 기존 `ProgressionUiBackdrop`을 쓰고, 제목·버튼·재화 표시·툴팁은 연구·유물·특성 메뉴와 같은 면·색상·형태를 사용한다. 기존 메뉴에서 사용하는 `NanumSquareRound-Bold SDF`와 지역화 폰트 폴백을 유지하며, 화면 전체를 별도의 새 테마나 폰트로 바꾸지 않는다. 세부 기준은 [공통 UI 스타일 정책](ui-style-policy.md)을 따른다.
- 다른 성장 탭과 같은 방식으로 상단의 월드 버튼을 선택한다. 공통 상단 탭과 하단 보스·사냥 버튼은 그대로 표시하고, 월드 탭에 선택 스프라이트를 적용한다. 어느 탭에서든 다른 탭으로 한 번에 이동할 수 있다. 하단 왼쪽의 뒤로는 직전 성장 탭, 홈은 연구 탭을 연다. 도움말은 포인트 공유·구매·선택 방법을 설명한다.
- 스테이지별 이미지는 `IsometricMaps`의 실제 프리팹을 **같은 구도와 비율로 촬영한 미리보기**로 제작한다. 육각형 이미지·마스크·프레임을 두지 않고, 실제 아이소메트릭 전장의 마름모 형태와 측면이 화면 중앙의 주인공으로 보이도록 배치한다. 맵을 둘러싼 불필요한 배경은 제거해 공통 배경과 자연스럽게 어울리게 하며, 여섯 맵의 크기·구도와 비율은 통일한다. 실시간 카메라가 아니라 미리 만든 이미지로 표시한다.
- 공통 배경 위에 맵을 직접 표시하고 그 아래에 이름을 둔다. 같은 정보 버튼이 해금된 맵에서는 ⓘ, 잠긴 맵에서는 유물 셀의 자물쇠를 표시한다. 아래에는 연구 노드 스프라이트와 연결선을 사용한다. 마우스를 맵에 올리면 미리보기가, 선택 노드에 올리면 노드와 체크가 1.08배로 확대된다. 포인터가 벗어나거나 스크롤하면 원래 크기로 돌아온다. 선택은 아래 노드의 체크와 기존 메뉴에 어울리는 색·강조로 표시하며 맵 주위에 새 육각형 테두리를 추가하지 않는다. 연결선은 이웃한 노드 사이에 놓고 맨 마지막 노드 뒤에는 그리지 않는다. 화면 밖에 다음 스테이지가 있으면 현재 보이는 마지막 항목의 선은 다음 항목 방향으로 이어질 수 있다.
- 특성 포인트는 특성 카드 화면에서 사용하는 책 아이콘과 동일한 잔액을 표시한다. 상단 선택 이름은 언제나 실제 선택된 스테이지를 나타낸다.

## 4. 스테이지 상태와 입력

| 상태 | 이미지와 이름 | 노드와 입력 |
|---|---|---|
| 해금·선택됨 | 실제 맵 이미지·이름·정보 아이콘 | 체크와 선택 강조를 표시한다. 다시 눌러도 선택이 해제되지 않는다. |
| 해금·미선택 | 실제 맵 이미지·이름·정보 아이콘 | 체크 없는 노드. 이미지 또는 노드를 누르면 선택한다. |
| 잠김 | 실제 아이소메트릭 맵의 형태와 색이 희미하게 보이도록 어둡게 처리하고 자물쇠를 표시한다. 검정 오버레이 약 65%를 시작점으로 맵별 가독성을 확인한다. 이름은 `???`로 표시하고 상세 툴팁은 열지 않는다. | 선택할 수 없다. 이미지나 노드 자체를 눌러도 포인트가 차감되지 않는다. |

선택은 항상 해금된 스테이지 하나만 유지한다. 선택 시 저장에 성공한 뒤 체크와 상단 이름을 바꾸며, 선택만으로 전투에 들어가지 않는다.

### 해금 버튼

1. 마우스를 잠긴 항목에 올리면 포인트 책 아이콘과 비용 숫자만 들어 있는 버튼을 표시한다. 카드에서 버튼으로 포인터를 옮길 때 버튼이 사라지지 않게 한다.
2. 터치에서는 잠긴 맵·자물쇠·선택 노드를 탭해 해금 버튼을 연다. 해금은 별도 버튼을 눌렀을 때만 시도한다.
3. 앞 스테이지가 잠겨 있으면 버튼을 비활성화하고 비용 숫자를 빨간색으로 표시한다. 선행 조건을 충족했지만 잔액이 부족하면 버튼 아래에 포인트 부족 안내를 표시한다. 구매가 가능하면 숫자는 연두색이다.
4. 성공 시 포인트 차감, 해당 스테이지 해금, 해당 스테이지 자동 선택을 한 번에 저장한다. 저장에 성공한 뒤 이미지·이름·선택 상태를 갱신한다. 저장 실패 시 이전 잔액과 잠금·선택 상태를 유지하고 재시도할 수 있게 한다.
5. 이미 해금된 항목에는 구매를 다시 적용하지 않는다. 빠른 반복 클릭이나 화면 재진입으로 중복 차감되지 않아야 한다.

### 가로 스크롤

마우스 드래그와 터치 스와이프로 목록을 움직인다. 스크롤이 시작되면 열린 툴팁과 해금 버튼을 닫는다. 드래그로 판정된 입력의 종료 시점에는 카드 선택·정보 열기·해금 버튼 클릭이 발생하지 않아야 한다. 잠시 움직임이 멎으면 마우스가 놓인 대상을 다시 확인한다. 정보 버튼 위에 마우스가 그대로 있으면 상세 툴팁을 다시 연다. 화면을 닫거나 다른 화면으로 이동할 때도 툴팁과 해금 버튼을 닫는다.

## 5. 스테이지 정보 툴팁

해금된 스테이지의 **정보 버튼에 마우스를 올리면** 버튼 옆에 툴팁이 열리고, 버튼에서 벗어나면 닫힌다. 처음 열릴 때 연구·유물·특성 메뉴와 같은 좌우 흔들림을 한 번 재생한다. 터치에서는 정보 아이콘을 탭해 열고, 다시 누르거나 바깥을 탭해 닫을 수 있다. 툴팁은 유물 상세창의 바깥 프레임·제목 띠·설명 띠를 사용한다. 목록 마스크 바깥에서 정보 버튼 오른쪽에 열고, 공간이 부족하면 왼쪽에 표시한다.

표시 순서는 다음과 같다.

1. **스테이지 이름**
2. **몬스터 경험치 배율**
3. **몬스터 체력 배율**

이번 툴팁에는 두 배율만 표시한다. 등장 대상 목록은 현재 표시하지 않으며, 스테이지별 특성은 나중에 추가한다. 특성이 아직 없을 때는 빈 특성 영역을 강제로 표시하지 않는다. 배율은 스테이지의 실제 전투 설정과 같은 데이터에서 읽고, 표시 형식은 `1.00배`처럼 소수 둘째 자리까지 통일한다. 표시값은 스테이지 자체의 배율이며 특성 카드 등 다른 효과를 합친 최종 배율은 아니다. 각 스테이지의 초기 배율과 적용 대상은 2절을 따른다.

잠긴 스테이지의 자물쇠는 해금 비용과 조건을 확인하는 버튼이다. 구매에 성공하면 같은 버튼의 아이콘이 ⓘ로 바뀌고, 다음 호버 또는 탭부터 상세 정보를 볼 수 있다.

## 6. 전투 진입과 재도전

- 사냥 버튼은 선택을 확정한 뒤 기존 일반 전투 진입 흐름을 사용한다. 연구 해금 몬스터, 특성 카드 효과, 결과 정산 및 전투 입장 연출을 유지한다.
- 선택된 스테이지의 경험치·체력 배율은 전투 시작 시 확정해 일반 사냥의 일반 몬스터에 적용한다. 보스 전투 전체와 보물상자는 제외한다. 툴팁은 같은 스테이지 데이터를 사용해 배율을 표시한다.
- 새 스테이지 전투는 기존 필드 5단계의 선택값과 단계별 젬스톤·경험치 보너스를 참조하지 않는다. 새 스테이지에서 별도로 정의하지 않은 젬스톤 보너스는 없다.
- 새 선택값에 해당하는 `IsometricMaps` 자식 하나만 활성화하고, 스폰·이동·공격의 경계로 쓰는 `BattlefieldArea`도 **전투 준비 전에** 같은 맵으로 연결한다. 스폰과 스킬은 그 런에 연결한 전장 경계를 사용한다.
- 보스 전투도 선택한 스테이지의 맵과 전투 영역을 사용한다. **보스 전투에서는 스테이지의 경험치·체력 배율과 추후 추가할 스테이지 특성 등 모든 스테이지 효과를 적용하지 않는다.** 스테이지와 무관한 기존 특성 카드 효과와 보스 전투 규칙은 유지한다.
- 전투 진행 중에는 스테이지를 변경하지 않는다. 일반·보스 전투 결과의 재도전은 해당 전투에 실제 사용한 스테이지로 다시 시작한다.

## 7. 스테이지 SO와 엑셀 텍스트

### 스테이지 SO

스테이지마다 같은 구조의 **개별 ScriptableObject(SO) 하나**를 둔다. 각 SO는 데이터 원본이며, 하나의 거대한 스테이지 데이터에 여섯 맵의 값을 몰아넣지 않는다. 스테이지를 추가할 때도 같은 형식의 SO를 추가해 관리한다.

| SO 항목 | 용도 |
|---|---|
| 고정 ID | 스테이지 식별과 저장에 사용. 표시명과 별개이며 이름이나 순서가 바뀌어도 유지한다. |
| 표시 순서 | 가로 목록의 배치 순서. ID와 독립적으로 편집한다. |
| 맵 프리팹·미리보기 참조 | `IsometricMaps`의 실제 맵 프리팹과 해당 맵을 촬영한 미리보기 연결. |
| 기본 해금 여부·선행 스테이지 | 숲의 기본 제공과 순차 해금 조건. 선행 스테이지는 고정 ID 또는 SO 참조로 식별한다. |
| 해금 비용 | 특성 포인트 정수 비용. 임시 비용은 2절을 따른다. |
| 일반 몬스터 경험치·체력 배율 | 일반 사냥에서 사용하는 실제 수치. 초기값은 모두 `1.00배`다. |
| 텍스트 키 | 엑셀에서 관리하는 표시 문구를 찾는 식별자. 고정 ID를 기반으로 연결한다. |

SO에는 **표시할 이름·설명·버튼 문구를 저장하지 않는다.** 텍스트 키는 문구가 아닌 연결용 식별자다. 추후 스테이지 특성이 추가되면 실제 효과 종류와 수치는 SO 데이터로 확장하고, 사용자에게 표시할 특성 이름·설명은 엑셀에서 관리한다. 효과 데이터가 없으면 빈 특성 안내를 표시하지 않는다.

맵 프리팹 참조는 프로젝트 에셋을 가리킨다. Main 씬의 `IsometricMaps` 자식과 그 `BattlefieldArea`는 App에서 각 스테이지의 맵과 연결한다. 씬 오브젝트를 SO에 직접 저장하거나 Progression이 Combat 구현을 직접 참조하지 않는다.

### 엑셀 텍스트 원본

스테이지 이름과 화면에 필요한 모든 사용자 표시 문구는 전용 **엑셀 원본**에서 관리한다. [StageText.xlsx](../../Assets/CursorHunter/Data/Authoring/StageText.xlsx)에서 한·영 문구를 편집한다. 현재 특성 카드의 [엑셀 가져오기 방식](../../Assets/CursorHunter/Progression/Editor/TraitCardTextWorkbook.cs)과 같은 흐름으로 연결한다.

| 엑셀 키 예시 | 용도 |
|---|---|
| `stage.forest.name` | 숲 스테이지 이름. 다른 스테이지도 고정 ID별 이름을 둔다. |
| `stage.forest.description` | 향후 스테이지 설명·특성 안내용. 현재 해금된 툴팁에는 표시하지 않는다. |
| `stage.ui.title`, `stage.ui.selected` | 화면 제목과 선택 스테이지 안내. 이름은 자리표시자로 조합한다. |
| `stage.ui.monster_xp`, `stage.ui.monster_hp` | 몬스터 경험치·체력 배율 항목명. 실제 배율 값은 SO에서 읽는다. |
| `stage.ui.locked_title` | 잠긴 스테이지 이름에 표시하는 `???`. |
| `stage.ui.insufficient_points` | 잔액 부족 안내. 구매 버튼의 비용 숫자는 스테이지 SO에서 읽는다. |
| 그 밖의 공통 키 | 뒤로·홈·도움말·저장 실패 등 해당 화면에서 새로 필요한 표시 문구. 기존에 같은 용도의 공통 지역화 키가 있으면 중복 생성하지 않고 재사용한다. |

엑셀은 키와 `ko`·`en` 열로 작성하고, 한국어를 필수로 한다. 기존 지역화 정책에 맞게 번역이 없는 경우 한국어로 대체한다. 화면은 언어 변경 시 다시 표시한다. 배율·포인트 비용처럼 계산에 쓰이는 숫자는 엑셀 문장에 고정하지 않고 SO에서 가져와 지역화 문구의 자리표시자에 넣는다. 엑셀에서 실제 문구를 수정하면 SO를 다시 편집하지 않아도 된다.

작성 흐름은 **엑셀 원본 → Unity 에디터에서 지역화 테이블 자동 갱신 → 실행 중 지역화 테이블 조회**다. 게임 실행이나 빌드에 Excel 프로그램·엑셀 파일 직접 읽기가 필요하지 않으며, 생성된 테이블은 빌드용 결과물이다. 엑셀을 저장하고 Unity로 돌아오면 반영하고, 수동 반영과 빌드 전 검증도 제공한다. 키 중복·필수 한국어 누락·SO의 텍스트 키 누락·잘못된 자리표시자가 있으면 변경을 확정하지 않고 오류를 알려 기존 정상 데이터를 보존한다.

### 저장과 UI

- 진행 데이터에는 해금한 스테이지 ID와 선택한 ID를 저장한다. 새 구매 기록이 없는 프로필은 숲만 해금·선택된 상태로 시작하며 기존 5개 필드의 레벨 기반 기록을 구매 기록으로 변환하지 않는다.
- 포인트는 특성 카드의 기존 `TraitCardProgressData.points`를 단일 기준으로 쓴다. 결제 직전에 선행 조건·해금 여부·잔액을 다시 확인하고, 차감·해금·자동 선택을 하나의 저장으로 확정한다. 카드 공개와 스테이지 구매는 서로의 최신 잔액을 반영한다.
- 저장 버전 13에서 기존 카드·재화·연구·유물·경험치를 보존한다. 구매한 스테이지 ID와 선택 ID는 포인트와 같은 저장 단위에 기록한다. 유효하지 않은 선택 ID는 소유한 기본 숲으로 안전하게 복구하고, 저장 실패 시 확정되지 않은 변경을 표시하지 않는다.
- 스테이지 항목은 게임 소유의 공통 프리팹 또는 재사용 컴포넌트로 만든다. 항목 수가 늘어나도 가로 목록과 연결선이 확장되어야 한다. 크기·앵커·간격·아이콘과 툴팁 위치는 에디터에서 조정할 수 있게 하며, 실행 때 임의로 작성된 배치를 덮어쓰지 않는다.
- 화면 전환은 App이 소유하고, Progression은 포인트·구매·저장을 관리한다. 맵·전투 구현을 Progression에서 직접 참조하지 않고 App이 선택된 데이터를 전투에 전달한다.

특성 카드·유저 레벨 초기화 치트는 포인트와 구매 스테이지를 함께 초기화한다. 저장이 성공하면 기본 숲만 해금·선택된다.

## 8. 남은 결정

| 항목 | 현재 상태 |
|---|---|
| 스테이지별 특성 | 나중에 추가한다. 현재는 별도 특성 설명을 표시하지 않는다. |
| 맵별 등장 몬스터 | 미정. 현재는 연구 해금에 따른 실제 편성을 사용하며 툴팁에 목록을 표시하지 않는다. |

## 9. 구현 후 검증

- 기본 숲, 단일 선택, 재선택, 잠긴 항목 클릭과 별도 해금 버튼, 선행 조건·포인트 부족, 해금 성공·자동 선택을 확인한다.
- 카드 공개와 스테이지 구매가 같은 잔액을 표시하고, 동시·반복 입력과 저장 실패에 중복 차감이나 부분 확정이 없는지 검사한다. 기존 프로필·신규 프로필의 저장 및 재실행 복원도 확인한다.
- 해금된 맵의 정보 버튼에 호버하거나 탭해 이름과 두 배율을 확인한다. 맵과 노드에서는 상세 툴팁이 열리지 않는지, 노드 확대가 복원되는지, 잠긴 버튼은 자물쇠로 표시되고 구매 후 같은 자리에서 정보 버튼으로 바뀌는지 확인한다.
- 일반 사냥에서 스테이지별 배율이 일반 몬스터의 경험치와 체력에 적용되고 보물상자는 영향을 받지 않는지 확인한다. 보스 전투에서는 스테이지 배율과 추후 스테이지 특성을 포함한 모든 스테이지 효과가 적용되지 않아야 한다. 모든 스테이지의 초기 1.00배와 1.00 미만·초과로 조정된 배율, 체력 소수점 올림과 최소 체력 1을 각각 검증한다. 특성 카드 경험치 효과는 함께 적용되고 기존 필드 단계의 젬스톤·경험치 보너스는 새 스테이지에 적용되지 않아야 한다.
- 마우스 호버, 터치 탭, 드래그와 스와이프, 목록 양끝, 스크롤 중 버튼 닫힘과 클릭 취소, 툴팁 화면 경계 및 화면 이탈을 확인한다.
- 6개 맵 각각의 프레임 없는 아이소메트릭 미리보기와 일반·보스 전투의 실제 맵·`BattlefieldArea`가 일치하고, 재도전 시 같은 맵을 사용하는지 확인한다. 일반 몬스터 편성과 정산·보스 동작의 회귀를 검사한다.
- 스테이지별 SO 추가·순서와 비용 변경, 중복 ID·누락 참조·잘못된 수치 및 선행 조건을 확인한다. 엑셀 수정 후 지역화 테이블과 한국어·영어 화면이 갱신되고, SO 배율·비용이 해당 표시와 실제 동작에 일치하는지 검사한다. 잘못된 엑셀은 기존 정상 테이블을 보존해야 한다.
- 1920×1080과 다른 화면 비율에서 세 항목의 가독성·잘림·공통 메뉴 입력, 한국어·영어와 긴 수치를 확인한다.
