# 새 연구 시스템 기획안

작성일: 2026-11-12  
상태: 설계 기준안. 사용자 확정 사항과 아래 제안 수치를 구분한다. 구현·밸런스 검증 전이다.

> 2026-11-12 변경: 별도의 연구 시작점 노드는 사용하지 않는다. 첫 테스트 맵은 초급 기본 공격 연구 6개를 선행 조건 없이 중앙 주변에 배치한다. 아래 코어 및 그루터기 관련 내용은 이전 제안이며, 전체 맵의 전투 진입·그루터기 해금 정책은 별도 확정이 필요하다.

## 1. 목적과 확정 범위

- 기존 연구 구매 기록은 보관만 한다. 새 연구의 모든 배치는 0랭크에서 시작한다. 기존 구매 기록을 새 랭크로 변환하지 않는다.
- 기존 연구 효과는 새 시스템의 전투 계산에 포함하지 않는다. 구매 기록, 사용 비용과 레거시 원본 데이터를 삭제하지 않는다.
- Unity 에디터에서 연구 종류·위치·연결·선행 수·최대 랭크·랭크별 효과·비용을 편집할 수 있게 데이터를 설계한다. 맵 에디터 구현은 이 기획의 범위 밖이다.
- 이 문서의 수치, 비용, 분기 구조는 구체적 **1차 밸런스 제안**이다. 실제 플레이·보상 속도 검증 전 확정 밸런스가 아니다.

## 2. 전환 정책 제안

### 2.1 레거시와 전투

- 전환 전 저장 원문을 별도 버전 백업으로 보존하고 복원 가능 여부를 검증한다. 현재 `TraitProgressionStore`의 저장 버전은 10이며 기존 `.before-v6` 백업을 덮어쓰지 않는다.
- `purchasedNodeIds`, 연구별 지출 내역과 구 연구 설정·구매 코드는 레거시로 읽기 전용 보관한다. 보관 데이터는 새 랭크, 선행 조건, 효과, 전투 입장 조건에 사용하지 않는다.
- 새 저장에는 지도 ID, 배치 ID, 랭크를 별도 기록한다. 전환 여부를 저장하고 재실행해도 0랭크 초기화를 반복하지 않는다. 백업 또는 전환 저장에 실패하면 원본을 덮어쓰지 않고 전환을 완료하지 않는다.
- 새 연구만 전투 스냅샷에 반영한다. 레거시 효과와 새 연구 효과를 합산하지 않는다. 연구 이외의 기존 특성 카드·유물 효과는 유지하며 각자의 기존 적용 단계에서 한 번만 반영한다.
- 기존 코어/`monster.01` 구매 여부를 사용하는 전투 입장 및 온보딩 조건은 새 연구 상태로 교체한다. 기존 보스 단계에 새 연구 해금 제한을 걸지 않는다.

### 2.2 재화와 나머지 진행도

- 제안: 기존 가넷·토파즈·자수정·사파이어·다이아몬드·드래곤 젬 잔액은 ID와 Int64 값 그대로 유지하고 새 연구 구매에 사용한다. 이미 연구에 소비된 금액은 환불하지 않는다. 0랭크는 연구 초기화이지 지갑 초기화가 아니다.
- 신규 프로필은 기존 시작 잔액 설정을 사용한다. 현재 기본 데이터의 가넷 245는 신규 초기값이며, 기존 저장에 추가로 지급하지 않는다.
- 보스 진행도·중복 정산 기록·유물·경험치·특성 카드·필드 단계는 유지한다. 저장 실패나 전환 재시도 시 잔액 복제·재지급이 일어나지 않아야 한다.
- 젬 잔액 보유와 해당 젬의 공급 몬스터 해금은 별개다. 보유 중인 상위 젬은 보존하지만, 새 지도는 각 젬의 공급 몬스터를 열기 전에 그 젬을 필수 비용으로 요구하지 않는다. 기존의 상위 젬 100:1 교환 정책은 유지한다.
- 전환 후 사용자의 전투 능력·열린 몬스터와 스킬은 새 연구 상태에 따라 줄어든다. 보스 진행도는 유지되므로 보유 연구 대비 높은 보스 단계에 진입할 수 있다는 점은 전환 안내와 난이도 검증에서 다룬다.
- 기존 지출 환불 없음과 기존 잔액 유지, 레거시 외의 진행도 유지는 사용자 선택을 위한 제안이며, 승인 전 구현하지 않는다.

### 2.3 시작 교착 방지

- 모든 배치는 0랭크로 시작한다. 시작 코어 1랭크는 무료이며 효과 없이 네 계열로 향하는 경로를 연다.
- 코어 다음의 그루터기 해금 1랭크도 무료다. 구매 이후 기존처럼 그루터기가 필드에 출현하고 가넷을 공급한다. 코어와 그루터기 구매를 새 전투 입장 조건으로 삼는다.
- 무료 연구도 명시적으로 구매한다. 자동 구매하지 않는다. 초보 안내와 기존 사용자 안내를 새 조건에 맞춘다. 무료 시작 경로와 유효한 기본 스탯만으로 첫 전투·보상·다음 구매가 가능한지 검증한다.

## 3. 현재 게임 기준

Main 씬의 `PlayerCombatStatsDefaults`는 공격력 2, 범위 1.7253809 월드 단위(기준 범위 1배), 공격 간격 0.8초, 치명타 확률 5%, 치명타 피해 2배, 보스 피해 1배다. 일반 필드 기본 시간은 15초, 상한은 30초다. 실제 원본은 Main 컴포넌트와 `game-data.en.json`이며, 연구 SO에 기본값을 복제하지 않는다.

- 커서 범위 연구의 내부 수치는 월드 단위다. UI 배율은 `현재 월드 반경 / GameInformation.BaseAttackRadiusWorldUnits`다. 예컨대 기준 1.7253809에서 +0.1 월드 단위는 약 1.06배다. +0.1 월드 단위를 +0.1배라고 표시하지 않는다.
- 스킬별 `damage`는 그 스킬의 고유 기본 피해에 더한다. 기본 공격력과 독립이다. 스킬 기본값은 실제 컨트롤러/씬 설정을 읽고 SO에 복제하지 않는다. 피해 결과는 전투의 반올림 규칙을 적용해 표시한다.
- 스킬 `radius`는 구현에 따라 기본 반경의 배율 또는 크기에 반영된다. 현재 토네이도·헤드샷·벼락·화염 배기와 마력 구체·레이저는 적용 방식이 다르므로 공통 `+0.2`가 같은 월드 단위가 아니다. 아래 값은 해당 스킬 `radius` 업그레이드에 전달하는 델타다. UI는 적용 후 실제 값 또는 정의된 배율을 표시한다.
- 기존 펫 전투 계약에서 확인된 성장 대상은 피해와 동시 타격 수다. 펫 범위 연구는 이번 기준안에서 제외한다. 동시 타격 수는 정수다.
- 유물은 전투 단계에서 별도 적용되는 효과가 있다. 연구 툴팁은 우선 **기본값 + 새 연구 + 기존 특성 카드** 기준의 연구 단계 수치를 표시하고, 유물의 전투 중 보정은 포함하지 않는다. 이 기준을 전체 정보 UI와 일치시키는 구현이 필요하다.

## 4. 연구 목록과 랭크별 효과

표의 효과 값은 0랭크에서 해당 랭크에 이르기까지의 **누적 효과**다. `+`는 기준값에 가산하고, `설정`은 해당 값을 사용한다. 동일 효과가 여러 배치에서 발생하면 가산 효과는 합산한다. 값 설정형은 동일 대상을 두 배치에서 동시에 사용하지 않는다. 각 대상의 적용 순서와 상한은 기존 전투 계약을 따른다.

### 4.1 시작 및 기본 공격

| 연구 정의 ID | 이름 | 최대 랭크 | 랭크별 누적 효과 | 1차 선행 조건 |
|---|---|---:|---|---|
| `research.core` | 연구 시작 | 1 | 효과 없음, 지도 경로 공개 | 없음 |
| `cursor.attack` | 기본 공격력 | 5 | +2 / +4 / +7 / +10 / +14 | 코어 1 |
| `cursor.radius` | 공격 범위 | 5 | +0.10 / +0.20 / +0.30 / +0.40 / +0.50 월드 반경 | 코어 1 |
| `cursor.interval` | 공격 간격 | 4 | -0.08 / -0.16 / -0.24 / -0.32초 | 코어 1 |
| `cursor.critical` | 치명타 확률 | 5 | +5 / +10 / +15 / +20 / +25%p | 공격력 1 |
| `cursor.critical_damage` | 치명타 피해 | 3 | +0.10 / +0.20 / +0.30배 | 치명타 확률 1 |
| `cursor.boss_damage` | 보스 피해 | 5 | +0.01 / +0.25 / +0.45 / +0.70 / +1.00배 | 공격력 1 |

치명타 확률은 최대 100%, 공격 간격은 기존 최소 0.05초를 넘지 않는다. 치명타 피해 연구는 기존 기본값·전투 스냅샷에 대상이 있지만, 현재 연구 증가량 생성 경로가 이를 내보내지 않으므로 새 연결 구현과 검증이 필요하다.

### 4.2 전투 스킬

각 스킬은 해금·피해·범위의 **3개 연구 정의**를 가진다. 해금은 최대 1랭크, 피해는 2랭크, 범위는 1랭크다. 각 스킬의 피해·범위 연구는 해당 스킬 해금 1랭크가 필요하다. 피해 및 범위 효과는 같은 스킬의 `damage`, `radius` 스냅샷 항목으로 전달한다.

| 스킬 / ID 접두사 | 해금 선행 | 피해 누적값 R1 / R2 | 범위 누적값 R1 |
|---|---|---|---:|
| 마력 구체 `skill.magic_ball` | 코어 1 | +2 / +5 | +0.20 |
| 토네이도 `skill.tornado` | 마력 구체 해금 | +3 / +7 | +0.20 |
| 헤드샷 `skill.headshot` | 마력 구체 해금 | +4 / +9 | +0.20 |
| 벼락 `skill.thunder` | 헤드샷 해금 | +5 / +11 | +0.20 |
| 화염 배기 `skill.flame_exhaust` | 벼락 해금 | +6 / +13 | +0.20 |
| 레이저 `skill.laser` | 벼락 해금 | +7 / +15 | +0.20 |

연구 정의 ID는 각각 `<접두사>.unlock`, `<접두사>.damage`, `<접두사>.radius`로 한다. 표의 접두사는 기존 전투 스킬 식별자다. 기존 데이터의 `damage` 증가값을 기준으로 2단계 연구를 하나의 다중 랭크 연구로 묶은 기준안이다. 스킬 동작을 실제로 시험해 피해와 범위의 체감 차이를 조정한다.

### 4.3 펫

| 연구 정의 ID | 이름 | 최대 랭크 | 랭크별 누적 효과 | 선행 조건 |
|---|---|---:|---|---|
| `skill.pet_baby_dragon.unlock` | 베이비 드래곤 해금 | 1 | 펫 활성화 | 코어 1 |
| `skill.pet_baby_dragon.damage` | 베이비 드래곤 피해 | 3 | +1 / +2 / +2.5 `damage` | 펫 해금 |
| `skill.pet_baby_dragon.targets` | 베이비 드래곤 동시 타격 | 2 | +1 / +2 `simultaneousHits` | 펫 해금 |

피해는 실전 반올림 이후 표시·피해가 같아야 한다. 소수 증가가 실제 표시값을 바꾸지 않는 상황이 발견되면 랭크 효과를 조정한다.

### 4.4 전투 환경과 몬스터

| 연구 정의 ID | 이름 | 최대 랭크 | 랭크별 누적 효과 | 선행 |
|---|---|---:|---|---|
| `field.duration` | 일반 필드 시간 | 3 | 20 / 25 / 30초로 설정 | 코어 1 |
| `monster.01.unlock` | 그루터기 해금 | 1 | 출현 활성화 | 코어 1, 무료 |
| `monster.01.production` | 그루터기 생산 | 3 | 3 / 4 / 5마리로 설정 | 그루터기 해금 |
| `monster.02`~`monster.10`의 `.unlock` | 각 몬스터 해금 | 각 1 | 해당 몬스터 출현 활성화 | 아래 순서 |
| `monster.02`~`monster.10`의 `.production` | 각 몬스터 생산 | 각 3 | 아래 표의 값으로 설정 | 해당 몬스터 해금 |

생산량은 **생성 기회 1회당 마릿수**다. 체력이나 생성 간격을 바꾸지 않는다. 동일 몬스터의 생산 설정 노드는 지도에 하나만 배치한다.

|---:|---|---|---|
| 01 | 그루터기 | 가넷 | 3 / 4 / 5 |
| 02 | 여왕벌 | 토파즈 | 3 / 5 / 8 |
| 03 | 독버섯 | 토파즈 | 3 / 5 / 8 |
| 04 | 가면유령 | 자수정 | 4 / 7 / 12 |
| 05 | 갑옷병사 | 자수정 | 4 / 7 / 12 |
| 06 | 눈요정 | 사파이어 | 4 / 7 / 12 |
| 07 | 벌집 | 사파이어 | 4 / 8 / 16 |
| 08 | 골렘 | 다이아몬드 | 4 / 8 / 16 |
| 09 | 봉오리 | 드래곤 젬 | 4 / 8 / 16 |
| 10 | 판도라 상자 | 드래곤 젬 | 4 / 8 / 16 |

몬스터 해금은 위 순서에서 바로 이전 몬스터 해금 1랭크를 선행으로 한다. 후반 몬스터 생산량은 기존 설정을 참고한 값으로, 화면 혼잡·난이도·재화량을 플레이 테스트해 조정한다.

## 5. 비용과 해금 순서의 1차 기준

최종 비용은 지도 배치의 랭크별 비용으로 명시한다. 런타임에 레거시의 티어 비용 배수를 다시 적용하지 않는다. 비용은 복수 재화를 허용하되 1차 지도는 아래 단일 재화 기준으로 시작한다. 모든 금액은 테스트용 제안이다.

- 무료: 코어 R1, 그루터기 해금 R1.
- 공통 비용표: R1 `100`, R2 `250`, R3 `500`, R4 `1,000`, R5 `2,000`. 각 금액의 재화는 아래에서 지정한다. 최대 랭크가 적으면 필요한 앞부분만 사용한다.
- 기본 공격, 필드 시간, 마력 구체 해금, 펫 해금과 각 강화: 가넷.
- 토네이도·헤드샷 해금 및 해당 강화: 토파즈. 벼락: 자수정. 화염 배기·레이저: 사파이어. 각 스킬 해금은 스킬 선행과 해당 젬 공급 몬스터 해금이 모두 필요하다.
- 몬스터 해금 비용은 02 가넷, 03 토파즈, 04 토파즈, 05 자수정, 06 자수정, 07 사파이어, 08 사파이어, 09 다이아몬드, 10 드래곤 젬이다. 각 몬스터 생산 연구의 재화는 해당 몬스터가 공급하는 젬이다. 시작 그루터기 생산은 가넷.
- 예: 여왕벌 해금은 그루터기 해금과 가넷 100, 가면유령 해금은 독버섯 해금과 토파즈 100. 따라서 새 재화의 최초 공급원을 열기 위해 그 재화가 필수인 순환은 없다.
- 한 노드에서 이전 랭크를 구매해야 다음 랭크를 구매한다. 인접 노드의 선행은 별도 지정이 없으면 1랭크다. 최대 랭크·랭크별 값·비용은 배치별 명시값으로 저장해 에디터에서 바꿀 수 있다.
- 재화 교환을 통해 상위 젬을 얻을 수 있지만, 선행 연구 조건을 우회하지 않는다. 시작 자금이 0인 구 저장도 무료 코어·그루터기와 첫 전투로 자립 가능해야 한다.

해당 표는 비용 증가와 공급 순서의 초기안일 뿐 목표 플레이 시간이나 수익률을 검증한 값이 아니다. 몬스터 드롭, 보스 보상, 기존 고액 잔액, 100:1 교환과 후반 생산량을 함께 시뮬레이션하고 Unity에서 플레이한 후 조정한다.

## 6. SO와 지도 데이터의 계약

**연구 정의 SO**: 영구적인 정의 ID, 현지화 키, 아이콘, 효과 대상 ID, 허용 연산과 표시 형식. 효과 대상을 `cursor.attackPower`, `skill.tornado.damage`, `monster.01.productionCount`처럼 명시한다. 정의는 플레이어 랭크·지갑을 소유하지 않는다.

**지도 SO 및 배치**: 영구 지도 ID, 배치 ID, 연구 정의 SO 참조, 좌표, 선행 배치 ID 목록, 요구 선행 개수, 최대 랭크, 랭크별 효과 목록, 랭크별 재화 ID/Int64 비용 목록. 동일 정의의 재사용은 허용하되 배치별 ID와 저장 랭크는 독립이다. 가산 효과는 합산하고, 활성·설정형 대상은 중복 배치를 검증 오류로 제한한다. 이 기획의 첫 지도는 각 정의를 한 번만 배치한다.

**진행 저장**: 지도 ID + 배치 ID별 랭크, 데이터 버전. 재화와 랭크는 같은 구매 단위로 저장한다. 이름, 에셋 경로, SO GUID, 배열 순서로 구매를 식별하지 않는다. 배치 ID 변경/삭제 시 별도 마이그레이션이 필요하다.

**정적 검증**: 고유 ID, 참조 누락, 순환 선행, 도달 불가 노드, 선행 개수 범위, 랭크 수와 비용·효과 수 일치, 음수 비용, 정수 전용 효과, 대상·연산 조합, 최대/최소 범위, 활성·설정형 중복, 해금 전 스킬/몬스터 강화, 비용 공급원 이전 도달 가능성을 검사한다. 선행 노드 연결과 비용 공급 경로는 독립적으로 검사한다.

## 7. 구매와 표시

- 플레이어가 노드를 클릭하면 최종 선행·랭크·모든 재화·저장 가능 상태를 재확인한다. 랭크 변경과 모든 비용 차감을 한 거래로 처리한다. 저장 실패 시 차감·랭크를 복구하고 성공 연출을 내지 않는다. PlayerPrefs 자체의 영속성 한계도 테스트하고 성공 보장 범위를 명확히 한다.
- 승인된 Dark `Tooltip.prefab` 기반의 게임 소유 Variant/래퍼를 사용한다. 제목은 중앙 정렬, 수치 사이와 재화는 실제 아이콘을 쓴다. 재화 이름과 설명형 문장은 기본 표시에서 제외한다.
- 0~최대 미만 랭크는 현재 효과가 반영된 실제 스탯 → 해당 랭크 구매 후 실제 스탯을 표시한다. 해금은 잠김 → 해금, 최대는 현재 값과 최대 랭크, 무료는 무료로 표시한다. 노드에 랭크를 표시한다. 조건 미충족·재화 부족 사유는 필요한 경우 간결하게 표시한다.
- 이전 상태와 미리보기는 같은 적용·제한·반올림 경로로 계산한다. 비용은 실제 지불 금액을 표시한다. 연구 화면 특성 카드용 툴팁과 구매 입력을 분리해 회귀를 방지한다.

## 8. 에디터 제작 전 완료 조건

1. 레거시 외 재화·진행도 보존 및 환불 정책 승인.
2. 49개 정의(시작 1, 기본 공격 6, 전투 스킬 18, 펫 3, 필드 1, 몬스터 20)의 ID·대상·연산·랭크별 효과·선행·비용 검토. 맵은 이 목록을 출발점으로 확장할 수 있다.
3. 각 스킬 기본값과 실제 최종 효과를 런타임에서 얻는 계약 확정. 특히 각 범위 단위 및 정수 피해 반올림 확인.
4. SO 직렬화, 배치 ID 안정성, 기존 지갑과 새 랭크의 원자적 저장 및 마이그레이션 구현 방식 확정.
5. 첫 지도·재화 공급 경로의 자동 도달성 검사와 수익·비용 시뮬레이션 설계.
6. 승인된 연구 툴팁, 상태별 입력, 무료 최초 전투, 저장 실패·복구·재실행 및 전투 스냅샷 검증 시나리오 정의.
