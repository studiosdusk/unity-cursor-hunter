# 특성 카드 시스템 설계서

작성일: 2026-11-16

상태: 카드 공개·선택·저장·연출과 보유 특성의 전투 효과를 구현했다.

## 1. 목표와 범위

전투로 유저 레벨을 올려 특성 포인트를 얻고, 무작위로 공개된 특성 카드 중 하나를 선택해 영구 효과를 얻는다. 한 번 선택한 카드는 보유 목록에 들어가며 이후 카드 풀에서 제외된다.

네 종류의 카드 SO와 엑셀 텍스트 원본을 `TraitCard_Canvas`에 연결했다. 기존 유저 경험치·레벨에서 새 특성 포인트를 지급하고, 카드 공개·즉시 선택·보유 목록·저장 복원과 공개/획득 연출을 구현했다. 획득한 카드의 효과는 전투 시작 시 스냅샷으로 복사해 해당 전투에 적용한다. 기존 특성 카드 기능과 데이터는 레거시로 보존한다.

## 2. 확정된 성장 규칙

| 항목 | 규칙 |
|---|---|
| 유저 레벨 | 전투에서 얻은 경험치로 상승한다. |
| 특성 포인트 | 유저 레벨이 1 오를 때마다 1개를 얻는다. |
| 특성 레벨 | 카드 종류와 관계없이 특성 카드를 선택한 총 횟수다. 카드를 선택하면 1 오른다. |
| 공개 비용 | 첫 공개는 1포인트다. 카드를 선택해 특성 레벨이 1 오를 때마다 다음 공개 비용도 1포인트 증가한다. |
| 공개 | 포인트를 한 번 사용해 이번 선택지를 함께 공개한다. 후보가 3종 이상이면 3종, 2종이나 1종만 남으면 남은 카드만 공개한다. |
| 선택 | 공개된 카드 하나를 누르면 추가 비용이나 확인 단계 없이 즉시 획득한다. |
| 영구 효과 | 선택한 카드의 효과는 영구적으로 편입된다. 카드의 발동 조건이 충족될 때 효과가 적용된다. |
| 선택 후 | 선택한 카드는 보유 목록에 추가되고 이후 카드 풀에서 제외된다. 남은 풀에서 다음 후보를 무작위로 정해 잠금 상태로 배치한다. |

특성 레벨과 유저 레벨은 별개다. 카드 공개만으로는 특성 레벨이 오르지 않으며, 이미 선택한 같은 카드를 다시 얻어 중첩하지 않는다. 선택하지 않은 카드는 풀에 남아 이후 다시 나올 수 있다.

### 공개 비용과 시작값

아직 카드를 선택하지 않은 **특성 레벨 0에서 첫 공개 비용은 1포인트**다. 이후 공개 비용은 `특성 레벨 + 1`로 계산한다. 공개만 할 때는 레벨과 다음 비용이 변하지 않고, 카드 선택을 완료했을 때 둘 다 1씩 오른다.

현재 준비된 4종을 모두 획득하는 예시는 다음과 같다.

| 획득한 카드 수 / 특성 레벨 | 남은 카드 종류 | 이번에 공개할 카드 | 공개 비용 |
|---:|---:|---:|---:|
| 0 | 4 | 3 | 1포인트 |
| 1 | 3 | 3 | 2포인트 |
| 2 | 2 | 2 | 3포인트 |
| 3 | 1 | 1 | 4포인트 |
| 4 | 0 | 없음 | 공개 불가 |

네 카드를 모두 획득하는 데 드는 공개 비용은 총 10포인트다. 유저 레벨과 경험치 요구량은 기존 `ProgressionLevelCurve`를 유지한다. 유저 레벨은 1부터 시작하고 현재 상한은 25이며, 다음 레벨 경험치는 `250 + 70 × (현재 유저 레벨 - 1)`이다. 기존 저장에 새 카드 진행도가 없으면 이미 오른 유저 레벨 수(`유저 레벨 - 1`)만큼 새 포인트를 한 번 초기 지급한다. 이후에는 새로 오른 레벨마다 1포인트를 지급한다.

## 3. 화면 구성

[Main.unity](../../Assets/CursorHunter/App/Scenes/Main.unity)의 `UICanvas/TraitCard_Canvas`에 사용자가 배치한 화면을 기준으로 한다. 현재 세 카드와 보유 아이콘 영역의 배치·크기를 존중하며 레거시 카드 화면의 레이아웃으로 교체하지 않는다.

| 영역 | 현재 구성 | 연결할 역할 |
|---|---|---|
| 배경 | `ProgressionUiBackdrop` | 기존 연구·유물 화면과 공유하는 배경 |
| 카드 선택지 | `TraitListLayout` 아래 `List` 프리팹 3개 | 공개된 카드의 제목·아이콘·효과를 보여주는 고정 슬롯 |
| 보유 목록 | `IconLayout` | 획득한 특성만 표시. `TraitIcon` 프리팹을 사용 |
| 특성 레벨 | `TraitLevel_Text` | 보유 카드 수에 따라 `특성 레벨 : N` 표시 |
| 공개 버튼 | `TraitCard_OpenButton` | 공개 비용·선택 안내·전체 획득 상태 표시 및 공개 입력 |
| 특성 포인트 | `TraitPointView` | 내부 TMP에 현재 포인트 잔액 표시 |

`IconLayout`에 현재 놓인 13개 `ItemFrame07_Dark_s`는 레이아웃 확인용으로 플레이 중 숨긴다. 실제 목록은 획득 순서대로 `TraitIcon`을 추가하며, 첫 열을 위에서 아래로 6개 채운 뒤 오른쪽 다음 열로 이동해 3열에 18개까지 배치할 수 있다. 미획득 특성이나 빈 고정 슬롯은 표시하지 않는다. `TraitIcon`의 배경과 아이콘은 기존 100×100 그리드 셀 안에 맞추며 `Count`, `Notify_New`, `Focus`는 사용하지 않는다. 보유 아이콘에 마우스를 올리면 DOTween으로 0.14초 동안 1.08배 확대하고 유물 화면과 같은 스타일의 툴팁에 카드 이름과 효과 설명을 표시한다. 포인터가 벗어나면 아이콘을 원래 크기로 돌리고 툴팁을 닫는다. 화면 종료·초기화 시에도 정리하며 획득 아이콘이 보유 목록에 도착하기 전에는 호버를 받지 않는다.

### 카드의 잠금과 공개

- 공개 전에는 카드 내용 위를 **잠금 이미지**로 가려 제목·아이콘·설명을 볼 수 없게 한다. 잠금 상태에서는 카드 선택이 발생하지 않는다.
- 공개 버튼으로 필요한 포인트를 한 번 지불하면 이번 후보가 반짝이며 잠금 이미지가 사라지고 제목·아이콘·효과를 함께 표시한다. 후보는 최대 3종이며 2종 또는 1종만 남으면 해당 카드만 표시한다.
- 공개된 카드의 어느 부분을 눌러도 해당 카드가 즉시 선택되도록 카드 전체를 입력 대상으로 삼는다. 제목·아이콘·설명 이미지가 입력을 가로채지 않도록 한다.
- 잠금 아이콘은 지정 IconPack의 `UI_Common_Lock_01_Silver`, 반짝임은 기존 UI의 `Image_Effect_Sparkle`을 참조한다. 게임 소유 `List` 프리팹에 `LockCover`, `RevealGlow`, `RevealSparkle0~3`를 배치했다.

카드의 `Text_ListTitle`, `Icon`, `Text_ListDesc`는 각각 SO와 엑셀에서 가져온 제목, 아이콘, 효과 설명에 연결한다. 현재의 `Free Reward` 문구와 포션 이미지는 예시이며 실제 카드 데이터가 아니다.

### 글꼴과 문구

- 한국어 텍스트는 `ResearchPrototype_Canvas`와 현재 게임 소유 `List` 프리팹에서 사용 중인 **NanumSquareRound-Bold SDF**를 기준으로 한다. 공통 글자·색·위계는 [UI 스타일 정책](ui-style-policy.md)을 따른다.
- 공급사 프리팹에 연결된 영문용 예시 글꼴을 한국어 출력의 기준으로 삼지 않으며 공급사 폰트 에셋을 수정하지 않는다.
- 필요한 카드 텍스트에만 글꼴을 지정하고, 실행 시 전체 TMP 텍스트를 일괄 변경하지 않는다.
- 퍼센트는 공통 UI 스타일 정책에 따라 소수 둘째 자리까지 표시한다. 예: `10.00%`. 계산 정밀도는 표시 형식과 분리한다.

## 4. 카드 공개와 선택 흐름

```text
전투 경험치 정산 → 유저 레벨 상승 → 특성 포인트 지급
                                      ↓
특성 화면: 잠긴 후보 카드 최대 3장 + 현재 레벨·포인트·공개 비용
                                      ↓ 공개 버튼과 포인트 지불
               후보 카드가 반짝이며 제목·아이콘·효과 공개
                                      ↓ 카드 하나를 누름
              선택 카드 보유 목록 추가 + 특성 레벨 1 상승
                    + 선택한 아이콘이 왼쪽 목록으로 이동
                                      ↓
                선택 카드를 제외한 풀에서 다음 카드 세팅
```

공개 전 후보는 보유하지 않은 카드 풀에서 정한다. 같은 공개에 동일 카드가 중복되지 않도록 뽑는다. 포인트가 부족하면 공개할 수 없고, 카드 내용도 보이지 않는다.

### 이어서 선택할 수 있는 상태 보존

포인트를 지불해 공개한 뒤 화면 이동이나 앱 종료가 발생해도 **공개된 카드와 선택 대기 상태를 유지**한다. 다시 들어왔을 때 포인트를 재차 소모하거나 후보가 바뀌지 않게 한다. 잠긴 후보도 선택 후 세팅한 상태를 보존해 화면 재진입으로 후보를 바꾸지 않게 한다.

공개 비용 차감과 공개 상태를 함께 저장하며, 카드 획득과 다음 잠긴 후보도 하나의 저장으로 확정한다. 저장에 성공한 뒤 새 상태를 화면에 공개하며 실패 시 이전 잔액과 후보를 유지한다. 공개 취소·환불과 별도 재추첨 기능은 이번 범위에 포함하지 않는다.

### 남은 카드가 3종 미만일 때

- 풀에 2종 또는 1종이 남으면 남은 카드만 후보로 배치하고, 공개 비용을 한 번 지불해 해당 카드만 공개한다. 후보를 채우기 위해 같은 카드를 중복으로 넣지 않는다.
- 후보가 1종이어도 공개 후 카드를 직접 눌러 획득한다. 자동으로 선택하지 않는다.
- 풀에 카드가 0종이면 더 이상 공개하지 않고 공개 버튼을 비활성화하며, 포인트도 차감하지 않는다. 모든 카드를 획득한 완료 상태를 표시한다.
- 사용하지 않는 슬롯은 내용과 잠금 이미지를 모두 숨기고 입력을 막는다. 레이아웃 자리 자체는 유지해 남은 카드의 위치를 옮기지 않는다. 완료 문구는 선택적으로 연결할 `Status Text`에 표시한다.

## 5. 공개와 선택 연출

후보 카드는 **세 장이 동시에 반짝이며 공개**하고, 선택할 때에도 **선택한 카드가 한 번 반짝인 뒤 아이콘이 왼쪽 보유 목록으로 이동**한다. 공개는 기본 0.65초, 선택 섬광과 아이콘 이동은 합계 0.55초이며 `TraitCardCanvas` Inspector에서 조절한다. UI 연출은 전투 시간 배율과 무관하게 진행하고 화면을 나가면 정리한다. 효과음은 아직 추가하지 않았다.

1. **공개 전:** 잠금 이미지가 카드 내용을 완전히 가린다. 후보가 존재하는 카드에만 잠금이 보이며, 호버하면 공개된 카드와 같이 확대되고 포인터가 벗어나면 복귀한다. 잠긴 카드는 클릭해도 선택되지 않는다.
2. **공개:** 버튼을 누르면 비용을 한 번 차감하고 포인트 표시를 갱신한다. 후보 카드가 동시에 짧게 빛나고 잠금 이미지가 사라진다. 2장이나 1장만 남으면 그 카드에만 같은 연출을 적용한다.
3. **선택 대기:** 공개 연출이 끝나면 선택을 허용한다. 잠긴 카드와 공개된 카드 모두 포인터를 올리면 0.14초 동안 원래 크기의 1.06배로 확대하고, 벗어나면 원래 크기로 돌아간다. 공개·획득 연출 중에는 확대하지 않으며, 호버 중 빛이나 파티클은 재생하지 않는다.
4. **즉시 획득:** 카드를 누르면 확인 창이나 추가 비용 없이 선택을 확정하고 보유 목록과 특성 레벨에 반영한다. 선택한 카드에 섬광을 한 번 재생하고 약 0.10초 뒤 아이콘이 왼쪽 `IconLayout`에 추가되는 `TraitIcon`의 위치로 이동한다. 선택하지 않은 카드는 흐려지며 사라진다. 아이콘 이동은 후속 시각 연출이며 획득 저장을 연출 종료까지 미루지 않는다. 효과는 다음 전투 시작 시 적용된다.
5. **다음 선택 준비:** 다음 후보가 있으면 잠긴 상태로 세팅하고 다음 공개 비용을 표시한다. 후보가 없으면 완료 상태를 표시한다.

공개 중에는 중복 공개 입력을 막고, 모든 후보가 보이기 전 선택 입력도 막는다. 선택 처리 중 반복 입력으로 여러 카드가 획득되지 않아야 한다. 연출 도중 화면을 벗어나도 실제 공개·획득 상태는 저장 결과에 맞게 복원한다. 저장 실패 시 성공 연출이나 포인트·카드 획득을 확정하지 않는다. 필요하다면 기존 UI의 짧은 클릭·획득 소리를 참고할 수 있으나 효과음의 사용 여부와 종류는 미정이다.

기존 Screen Space Overlay 캔버스에서 원본 파티클의 섬광을 그대로 표시하도록 `TraitCardRevealBaker`가 0.65초를 24프레임으로 렌더링한다. 결과는 `Progression/Art/TraitCards/CardFlashBlue.png`이며, `List/CardFlash`의 RawImage가 전용 가산 합성 머티리얼로 재생한다. 실행 중 별도 카메라나 파티클 인스턴스는 만들지 않는다. 원본 효과를 다시 가져올 때는 그래픽 장치가 있는 Editor에서 `Tools > Cursor Hunter > Trait Cards > Rebuild Reveal Effect`를 실행한다. 기본 UI 배경의 부유 입자는 이 공개·선택 연출과 별개다.

### 글자 스타일

`ResearchPrototype_Canvas`와 같은 `NanumSquareRound-Bold SDF` 및 공용 기본 머티리얼을 사용한다. 특성 레벨은 64, 공개 버튼은 최대 42, 카드 제목은 최대 40으로 표시한다. 설명은 밝은 회백색 `#E3ECF8`, 기본 34·최소 32이며 실제 네 카드의 한국어 설명은 모두 34 크기로 들어간다. 설명 영역은 좌우 26 여백과 높이 190을 확보하고 단어 단위로 줄바꿈한다. 문구와 수치 원본은 엑셀·SO를 유지하며 전체 프로젝트의 TMP 줄바꿈 설정은 바꾸지 않는다.

## 6. 특성 카드 4종

카드 이름은 현재 엑셀에 등록된 임시 이름이다. 아래 수치는 기획 초안이며 실제 전투에는 카드 SO의 현재 게임 효과 설정이 적용된다.

| 카드 | SO ID | 발동과 효과 | 결정이 필요한 세부 사항 |
|---|---|---|---|
| 행운의 주사위 | `trait_card.lucky_settlement` | 전투 종료 시 10% 확률로 획득 젬스톤 6종을 5배로 정산한다. 경험치와 유물은 대상이 아니다. | 확률과 배율은 카드 SO에서 조절 |
| 보물상자 | `trait_card.treasure_chest` | 일반·보스 전투 시작 시 SO의 확률과 개수로 상자가 나타난다. 공격해 파괴하면 몬스터 SO의 보상을 얻는다. | 기본 체력 10, 가넷 100, 경험치 0은 보물상자 몬스터 SO에서 조절 |

보상 5배는 **최종 젬스톤 획득량이 원래 보상의 5배**라는 뜻이며 상자에서 얻은 젬스톤도 포함한다. 정산 가능한 종료에서 한 번 판정하고 결과를 `RunResult`에 고정한다. 보스 실패·초기화 등 보상 폐기 시에는 지급하지 않는다. 정산 재시도에서 결과를 다시 추첨하지 않는다.

## 7. 데이터와 기존 구조

- 카드 한 종류당 [TraitCardDefinition](../../Assets/CursorHunter/Data/Runtime/TraitCardDefinition.cs) SO 하나를 사용한다. `stableId`는 표시 이름과 독립적인 고정 ID다.
- `presentation`은 텍스트 키, 카드 아이콘과 표시 순서를 보유한다. 아이콘은 지정된 `2D Minimal-IconPack/Icons/512` 에셋을 참조한다.
- `gameplay`는 효과 종류와 해당 효과의 확률·배율·시간·증가율 등의 실제 게임 수치를 보유한다.
- 카드 제목과 설명의 원본은 [TraitCardText.xlsx](../../Assets/CursorHunter/Data/Authoring/TraitCardText.xlsx)다. SO에는 표시 문장 대신 키를 둔다. 엑셀을 Unity 현지화 테이블로 가져오며 `TraitCardTextFormatter`로 수치 자리표시자를 SO 값으로 치환한다.
- 보유 목록 아이콘은 선택한 카드의 SO 아이콘을 `TraitIcon/ItemIcon`에 표시한다. 중복 획득이 없으므로 개수 표시는 숨긴다.
- 보유 아이콘 툴팁은 씬에 배치된 `TraitOwnedTooltip`과 `TraitCardTooltip`을 사용한다. 제목·설명은 `TraitCardText.xlsx`에서 생성한 현지화 테이블을 구독하고 설명의 수치는 해당 카드 SO에서 치환한다. 툴팁은 화면 밖으로 나가지 않게 위치를 조정하고 입력을 가로채지 않는다. 아이콘이 획득 연출로 이동하는 동안은 호버를 받지 않는다.
- `List`와 `TraitIcon`은 게임 소유 프리팹을 사용한다. 공급사 원본을 수정하거나 런타임에 화면 전체를 다시 생성하지 않는다.

## 8. 진행 상태와 전투 연결 설계

진행도 저장 version 12의 `newTraitCards`에 포인트 잔액, 보유 카드 ID 목록, 현재 후보 카드 ID와 공개 여부를 기록한다. `hasNewTraitCardProgress`로 최초 전환 여부를 구분해 재실행 때 초기 포인트를 중복 지급하지 않는다. 특성 레벨은 중복 없는 보유 카드 수로 계산한다. 기존 경험치·유저 레벨·지갑을 재사용하고 레거시의 보유 ID·잔액은 기존 필드에 보존한다. Main의 `useNewTraitCardSystem`이 켜져 있을 때 레거시 카드 효과와 포인트 추가 지급은 사용하지 않는다.

하나의 전투에서 여러 유저 레벨이 한 번에 오르면 오른 레벨 수만큼 포인트를 지급한다. `GrantSettledRun`은 일반·보스 런 ID 영수증과 보상·경험치·포인트를 함께 저장한다. 기존 영수증 목록 필드명 `settledBossRunIds`는 호환성을 위해 유지하되 일반 런 영수증도 담는다. 같은 전투 결과의 정산 재시도와 저장 재로드에서 중복 지급을 막는다. 재화·경험치·새 특성 포인트는 Int64를 사용한다.

### 사용자가 배치한 UI 연결

`Main / UICanvas / TraitCard_Canvas`의 `TraitCardCanvas` 컴포넌트에 아래 항목을 연결했다. 사용자 배치를 그대로 사용하고 버튼이나 텍스트를 자동 생성하지 않는다.

| Inspector 필드 | 연결할 오브젝트 |
|---|---|
| `Reveal Button` | `TraitCard_OpenButton`의 Button |
| `Reveal Button Text` | 위 버튼의 `Text` TMP. 공개/획득 중·선택 안내·완료 상태 표시 |
| `Reveal Button Cost View` | 위 버튼에 미리 배치한 `RevealCostView`. 공개 비용 표시 전체 |
| `Reveal Button Cost Heading` | `RevealCostHeading` TMP. `특성 카드 공개` 문구 |
| `Reveal Button Cost Value` | `RevealCostRow/RevealCostValue` TMP. 다음 공개 비용 숫자 |
| `Points Text` | `TraitPointView`의 `Text (TMP)` |
| `Level Text` | `TraitLevel_Text`. `Level Text Format`은 `특성 레벨 : {0}` |
| `Reveal Cost Text` | 다음 공개 비용을 표시할 TMP |
| `Status Text` | 선택 안내·포인트 부족·완료·저장 실패를 표시할 TMP (선택 사항) |

포인트 잔액은 숫자만 출력하며 제목·재화 아이콘은 사용자 배치를 사용한다. 공개 버튼의 비용은 숫자와 `Item_Book_01_Purple` 아이콘으로 표시한다. 공개할 수 있으면 제목과 비용 숫자는 연두색(`#B8F58A`), 포인트가 부족하면 다홍색(`#FF7864`)이며 아이콘의 색상은 그대로 유지한다. 공개/획득 연출·선택 대기·전체 획득 중에는 비용 영역을 숨기고 상태 안내를 표시한다. `Reveal Cost Text`와 `Status Text`는 선택 사항으로 비워 두었다. 포인트 부족·공개/획득 연출·선택 대기·전체 획득 시 버튼을 비활성화한다. `Reveal Button`을 연결했으므로 OnClick을 따로 등록하지 않는다. 외부 버튼 이벤트를 사용할 때는 `TraitCardCanvas.RevealCards()`를 호출할 수 있다. 텍스트와 아이콘은 클릭을 가로채지 않으며, 버튼에는 기존 한국어 폰트를 사용한다.

### 전투 중 유저 레벨·경험치 표시

`UICanvas/InGameObjects`의 `PlayerExperiencePresenter`가 사용자가 배치한 `ExpSlider`와 내부 레벨·경험치 TMP를 관리한다. `PrototypeRunHud`가 전투 시작·종료·초기화를 전달하고, App의 Presenter가 Combat의 `RewardResolved` 이벤트를 받아 처치 즉시 갱신한다.

- 전투 시작 때 저장 경험치를 기억하고 이번 전투의 누적 경험치를 더해 표시한다. HUD를 다시 열거나 같은 알림을 반복 수신해도 중복 누적하지 않는다.
- 슬라이더는 현재 레벨에서 얻은 경험치 / 다음 레벨 필요 경험치다. 레벨업하면 남은 경험치로 다음 구간을 표시한다. 여러 레벨을 한 번에 넘는 경우도 동일하다.
- 레벨 숫자는 유저 레벨이며 특성 레벨과 별개다. 기존 상한 25에서는 `MAX`와 가득 찬 바를 표시한다.
- 표시용 슬라이더이므로 드래그나 키보드로 값을 바꿀 수 없다. 사용자 배치·아이콘·숫자 폰트는 유지한다.
- 전투 중 표시는 미리보기이고 영구 경험치·레벨업 특성 포인트는 기존 정산 시 함께 저장한다. 정산 직후 이미 저장된 값에 전투 경험치를 다시 더하지 않는다. 보상이 폐기되는 전투는 종료 시 저장 경험치로 돌아간다.

### UI 버튼용 진행도 초기화

Main의 `HuntManager` 오브젝트를 버튼 OnClick에 넣고 `HuntManager.ResetTraitCardProgress()`를 선택한다. 버튼은 사용자가 배치·연결한다. UI에서 호출하는 용도이며 전투 중단 처리는 추가하지 않는다.

- 신규 특성 카드 보유 목록·특성 레벨·특성 포인트를 모두 0으로 초기화한다. 공개 상태를 해제하고 전체 카드 풀에서 잠긴 후보를 최대 3장 다시 준비한다. 첫 공개 비용은 다시 1포인트다.
- 유저 누적 경험치를 0으로 초기화해 레벨 1부터 시작한다. 카드 화면과 경험치 표시를 갱신하고, 진행 중인 카드 공개·아이콘 이동 연출을 정리한다.
- 카드 진행도와 경험치를 함께 저장한다. 저장 실패 시 기존 값을 유지하며, 성공한 초기화는 재실행 후에도 유지된다. 반복 호출로 포인트가 환급되지 않는다.
- 연구·재화·유물·보스 진행도·레거시 특성 데이터와 기존 정산 영수증은 유지한다. 저장 대기 중인 전투 보상이 있으면 먼저 정산하며, 정산 저장에 실패하면 초기화도 진행하지 않는다.

### 전투 효과 연결

App의 `TraitCardCombatLoadout`이 보유 카드 SO의 수치를 전투 시작 시 불변 스냅샷으로 복사하고, Combat의 독립 효과 모듈이 이를 소비한다. 효과 발동과 보물상자 추가 보상의 확률 판정은 전용 난수를 사용해 기존 몬스터·유물 난수 스트림을 소비하지 않는다. 전투 중 SO나 보유 상태를 바꿔도 현재 런의 효과는 바뀌지 않는다.

보물상자는 기존 몬스터와 같은 [MonsterDefinition SO](../../Assets/CursorHunter/Data/Definitions/Traits/TreasureChestMonster.asset)와 공용 몬스터 루트를 사용한다. 상자는 한 번만 생성되고 처치 수·보스 처치·일반 몬스터 경험치 보너스에 포함되지 않는다. 상자 SO에 별도 경험치나 추가 재화가 설정되면 기본 수치대로 지급하고 해당 젬스톤을 전투 HUD에 표시한다. 상자 기본 재화는 가넷 100개다. 플레이어 진행도를 사용하는 밸런스 테스트에도 효과를 적용하지만 테스트 결과는 저장하지 않는다.

상자의 타격 영역 크기는 몬스터 SO의 `Hit Area Width`·`Hit Area Height`로 조절하며, 생성 시 그 중심을 상자 스프라이트 중심에 맞춘다. 피격 시 `TreasureChestVisual`의 `TreasureChestHitFeedback`이 본체만 흔들고 밝게 표시한다. 그림자와 타격 영역은 움직이지 않으며 연속 피격 시 연출을 다시 시작한다. 마지막 타격도 동일하게 연출한 뒤 상자를 제거한다. 재화는 마지막 타격에 즉시 확정하고 상자는 더 이상 공격받지 않으므로 연출 중 보상이 중복되지 않는다. 전투 일시정지 중에는 피격 연출도 멈춘다. 시간·흔들림 각도·밝기는 프리팹에서 조절한다.

커서 강화는 전투 시간 기준으로 주기를 판정하며 일시정지·입장 연출 중에는 시간이 흐르지 않는다. 반경 배율을 현재 연구·유물 반경에 적용하고 효과가 끝나면 원래 반경을 복원한다. 일반 몬스터 경험치는 기존 필드 배율과 특성 증가율을 함께 적용하고 소수점은 전투 중 누적해 정수 단위로 지급한다.

## 10. 구현 후 확인할 항목

- 레벨을 여러 번 한꺼번에 올려도 포인트가 오른 레벨 수만큼 한 번 지급된다.
- 잠금 상태에서 카드 내용이 가려지고, 포인트 부족 시 공개할 수 없다.
- 공개 비용의 숫자 옆에 포인트 아이콘이 보이고, 비용을 지불할 수 있는지에 따라 제목과 숫자가 연두색 또는 다홍색으로 갱신된다. 공개/선택 대기 및 완료 상태에서는 비용 영역이 숨겨진다.
- 첫 공개 비용은 1포인트이며 특성 레벨 0·1·2·3의 공개 비용은 각각 1·2·3·4포인트다. 공개만 할 때는 레벨과 비용이 변하지 않는다.
- 공개 시 비용을 한 번 차감하며 후보가 최대 세 장 공개된다. 선택 시 추가 비용이나 확인 창 없이 한 장만 획득된다.
- 공개 시 남은 후보만 동시에 반짝이며 잠금이 해제되고, 선택한 카드의 아이콘이 왼쪽 보유 목록의 `TraitIcon` 위치로 이동한다. 아이콘 이동이 실제 획득이나 특성 레벨 증가를 지연하지 않는다.
- 획득 카드는 `TraitIcon`으로 보유 목록에 나타나고 이후 후보에서 제외된다. 다음 공개 비용은 1 증가한다.
- 보유 아이콘에 호버하면 각 카드의 현지화된 제목과 SO 수치가 포함된 설명이 나타나며, 포인터 이탈·화면 전환·초기화 시 닫힌다.
- 화면 이동·종료·저장 실패·반복 입력과 전투 정산 재시도에서 카드나 포인트가 복제·유실되지 않는다.
- 남은 카드가 2종·1종이면 중복 없이 해당 카드만 공개하며, 마지막 1종도 직접 선택해야 획득한다. 0종일 때는 공개가 막히고 포인트가 차감되지 않는다.
- 한국어 글꼴과 엑셀 문구가 정상 표시되고, SO 수치를 바꾸면 설명에도 같은 수치가 반영된다.
- 각 효과의 발동 조건과 미발동 조건을 검증하고, 보스·일반 전투 및 작은 경험치 수치의 경계를 확인한다.
- 기존 배경 전용 Play Mode 테스트의 자식 수 가정을 현재 레이아웃에 맞게 갱신한다.
