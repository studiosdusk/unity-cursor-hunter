# Cursor Hunter v0.0.4 현재 상태·인수인계 핵심본

작성일: 2026-09-21
Unity: **6000.3.13f1**
담당: **준영(특성·데이터·경제·저장·초기 통합)** / **승기(일반·보스 전투)**

이 문서는 팀이 바로 개발을 이어가기 위한 짧은 기준 문서다. 화면별 와이어프레임과
전체 수치표는 [상세 기획서](../cursor-hunter-game-design-v0.0.4.md), 코드 경계는
[architecture.md](architecture.md)와 [contracts.md](contracts.md), 에셋은
[trait-ui-assets.md](trait-ui-assets.md)를 확인한다. 문서가 충돌하면 이 문서의
런타임 계약과 `TraitCatalog`의 실제 값을 우선한다.

## 1. 목표와 소유권

- 목표 플레이 시간: 약 **150분**, v5 보스 최초 격파 후 엔딩.
- 게임 루프: `Main → 일반 Field → 정산 → 특성/전리품/펫 → 보스 Field → 다음 해금`.
- 일반 몬스터는 공격하지 않는다. 보스만 공격과 파훼 이벤트를 가진다.
- 준영: `Progression`, 특성 UI·구매·초기화, 경제·밸런스·저장, App 연결.
- 승기: `Combat`, 커서 판정, 몬스터 생성·이동·HP, 일반/보스 전투, 스킬 실행, 전투 HUD/VFX.
- 공통 계약: `Contracts`를 통해서만 Progression과 Combat이 통신한다.

## 2. 현재 프로젝트 구조

실제 런타임은 `Assets/CursorHunter/App/Scenes/Main.unity`를 사용한다.

```text
Assets/CursorHunter/
  App/        Main, 화면 전환, 필드 시간, 정산 HUD
  Combat/     커서 공격, 몬스터, 보스, 스킬 실행
  Contracts/  Progression ↔ Combat 읽기 전용 스냅샷과 RunResult
  Data/       MonsterDefinition 등 authored 데이터
  Progression/특성 UI, TraitCatalog, 저장소, 경제
```

`ProgressionSandbox`와 `CombatSandbox`는 모듈 검증용이다. 통합 빌드에는 Main만
등록하고 Sandbox를 Additive로 로드하지 않는다.

현재 구현된 프로토타입:

- 특성 화면 Stat/Skill/Monster/전리품/Pet 데이터와 구매·초기화 UI
- PlayerPrefs JSON 기반 특성·젬스톤·전리품 조각 저장
- 런 시작 시 `ProgressionCombatSnapshot` 생성
- 일반 필드 15~60초, 보스 필드 60초 고정
- 몬스터 HP·젠 주기·가넷 보상·보너스 젬스톤·전리품 조각 결과 생성
- 치명타 판정과 HUD 피드백
- `RunResult.Rewards`의 App 정산 및 실행 중 `RunId` 중복 방지
- 일반 몬스터 월드 체력바와 고화질 런타임 설정

## 3. 전투 연결 계약

```text
TraitScreenController.CreateCombatSnapshot()
        ↓ (런 시작 시 1회)
HuntManager.StartRun()
        ↓
CombatRunController(snapshot)
        ↓
RunResult(정산 정책, 처치 수, DPS, Rewards)
        ↓
HuntManager.SettleRunRewards()
        ↓
TraitScreenController.GrantResourceRewards(rewards)
```

승기는 전투 중 `TraitScreenController`나 PlayerPrefs를 직접 참조하지 않는다.
스냅샷은 런 중 변경하지 않으며, `RunResult`만 App으로 반환한다.

핵심 코드:

```csharp
// 일반 필드: 스냅샷 값, 보스 필드: 항상 60초
float seconds = HuntManager.GetRunDuration(mode, snapshot, 15f);
```

```csharp
// Eligible 결과만 한 번 정산
if (result.SettlementPolicy == RunSettlementPolicy.Eligible &&
    progression.GrantResourceRewards(result.Rewards))
{
    // HuntManager가 RunId를 기억해 중복 지급을 막는다.
}
```

정식 출시 전에는 `RunId` 정산 완료 여부도 영구 저장소에 기록해야 앱 강제 종료 후
중복 보상을 막을 수 있다.

## 4. 확정 성장 규칙

### Stat

모든 행은 독립적으로 먼저 투자할 수 있다. 행 안의 노드는 순서대로 해금한다.

| 행 | 핵심 값 | 해금/강화 재화 |
|---|---|---|
| 공격력 | 1 → 3 → 6 → 10 → 16 → 24 → 35 → 50 → 70 → 100 | 가넷 → 토파즈 → 자수정 → 사파이어 → 다이아몬드 → 드래곤 젬 |
| 반경 | 초안의 작은 원형을 기본값으로 사용 → 1/32 → 1/16 → 1/8 → 1/4 → 전체 화면 | 가넷 → 토파즈 → 자수정 → 사파이어 → 다이아몬드 → 드래곤 젬 |
| 다중 클릭 | 1회 → 더블 → 트리플 → 쿼드 → 자동 무한 | 가넷 → 토파즈 → 자수정 → 사파이어 → 드래곤 젬 |
| 치명타 | 0% → 5% → 10% → 20% → 30% → 50% → 75% → 100% | 가넷 → 토파즈 → 자수정 → 사파이어 → 다이아몬드 → 드래곤 젬 |
| 젬 수집 | 접촉 클릭 → 접촉 자동 → 자석 → 자석 확대 → 전체 자동 | 가넷 → 토파즈 → 자수정 → 사파이어 → 드래곤 젬 |
| 보스 공격력 | 1 → 2 → 3 → 4 → 5 | 보스 티어 젬 |
| 일반 필드 시간 | 15 → 20 → 25 → … → 60초 | 가넷 → 토파즈 → 자수정 → 사파이어 → 다이아몬드 → 드래곤 젬 |

일반 필드는 처음 15초이며 시간 노드 한 단계마다 5초 증가한다. 보스 필드는 항상
60초다. 치명타는 실제 피해를 2배로 계산하고 HUD에 `치명타! ×2`를 표시한다.

### Skill

스킬은 종류 해금 후 같은 아이콘을 사용하는 `피해량 → 범위 → 쿨타임` 3단계 강화다.

| 순서 | 스킬 | 해금 |
|---:|---|---|
| 1 | 파이어볼 | 시작 |
| 2 | 라이트닝 볼트 | v1 |
| 3 | 프리즈닝 | v2 |
| 4 | 허리케인 | v2 |
| 5 | 메테오 | v3 |
| 6 | 드래곤 브레스 | v4, 최종 스킬 |

### Monster

이름은 디자인 확정 전까지 `Monster1~Monster20`이다. 낮은 티어 몬스터는 후반에도
계속 중첩 출현한다. 해금 후 각 몬스터의 생산량 I/II/III을 추가 구매한다.

| 해금 | 몬스터 | 특징 범위 |
|---|---|---|
| 시작 | Monster1 | 기본형 |
| v1 | Monster2~5 | 빠른 이동, 은신, 고HP, 방패 |
| v2 | Monster6~9 | 점프, 소형, 대형·느림, 지그재그 |
| v3 | Monster10~13 | 순간이동, 방향 급변, 원형 이동, 분리 |
| v4 | Monster14~16 | 잔상, 크기 변화, 가장자리 재등장 |
| v5 | Monster17~20 | 다중 방패, 급가속, 군집, 특징 조합 |

종별 기본 HP·젠 주기·가넷 보상·드롭 값은 `TraitCatalog`가 기준이며 상세표는
[상세 기획서](../cursor-hunter-game-design-v0.0.4.md)의 Monster 밸런스 표를 따른다.

### 젬스톤

게임 시작에는 **가넷만** 노출한다. 토파즈·자수정·사파이어·다이아몬드·드래곤 젬은
보스 접근 조건과 `Stat → 젬 수집` 해금 노드를 모두 만족한 뒤 보유 목록과 랜덤 드롭
후보에 추가한다. 해금된 젬스톤만 가중치 합으로 확률을 정규화한다.

```text
가넷(시작) → 토파즈(v1) → 자수정(v2) → 사파이어(v2) → 다이아몬드(v3) → 드래곤 젬(v4)
```

현재 UI의 `TryRollGemstoneDrop`은 확률 규칙을 보여준다. Combat의 전체 가중치 풀
추첨은 다음 계약 확장에서 연결한다.

### 전리품

- 일반 몬스터 20개와 보스 5개를 각각 별도 도감으로 둔다.
- 최초 해금 조각 1개, 이후 강화 비용 `2 → 3 → 5 → 10`개.
- 효과는 대상 피해, 생산량, 수확량, 전리품 확률, 보스 피해, 정산 보너스, 보너스 드롭을 순환한다.
- 몬스터 처치와 보스 클리어 결과에 조각 보상 후보를 넣고 App 정산에서 지급한다.
- 같은 몬스터 조각은 다른 몬스터 전리품에 사용할 수 없다.

### Pet

기본 1마리이며 커서 주변의 별도 반경에서 자동 공격한다. 영역·피해·공격 주기·대상
수 강화 노드를 둔다. 현재는 카탈로그와 UI 계약까지 준비되어 있고 실제 자동 공격은
Combat 확장 작업이다.

## 5. 비용과 보상 기준

- 테스트 모드에서는 모든 노드가 열리고 무료다. `testModeUnlockAll`과
  `testModeFreeUpgrades`는 출시 전에 끈다.
- 실제 모드 비용은 `TraitCatalog`의 `currencyId`, `costAmount`가 단일 원장이다.
- 해금·강화 비용은 노드의 `CostGemstoneId`가 단일 기준이다. 같은 행 안에서도 보스 구간이
  올라갈수록 가넷에서 다음 티어 젬스톤으로 결제 재화가 이동한다.
- 공격력·반경·다중 클릭·치명타·젬 수집·일반 필드 시간은 각 노드에 서로 다른 젬스톤 ID를
  명시한다. Skill은 스킬별 전용 젬스톤, Monster 생산량은 몬스터 해금 티어의 젬스톤을 쓴다.
- 전리품은 전용 조각 ID를 사용한다.
- 몬스터는 기본 가넷을 확정 지급하고, 해금된 보너스 젬스톤과 전리품 조각을 별도 확률로 판정한다.
- 보스 보상 초안은 v1~v5에 가넷·해금 티어 젬·전리품 조각·최초 클리어 보너스를 배정한다.
- 비용·드롭·보스 보상 전체 숫자는 상세 기획서와 `TraitCatalog.CreateRuntimeDemo()`가 동일해야 한다.

## 6. 승기 구현 순서

1. 런 시작 시 스냅샷을 한 번 생성하고 몬스터 Spawn Plan을 만든다.
2. 일반 필드 시간은 스냅샷의 15~60초, 보스는 60초를 사용한다.
3. `snapshot.Monsters`의 해금 종을 모두 후보에 넣고 HP·젠 주기·생산량·보상 값을 읽는다.
4. 커서 피격은 `ICombatTarget.ApplyDamage()`를 통해 처리하고 치명타 이벤트를 HUD에 전달한다.
5. 일반 필드 만료 시 살아 있는 몬스터는 보상 없이 제거한다.
6. `RunResult.Rewards`를 App으로 넘기고 직접 재화 저장을 하지 않는다.
7. 보스 전투가 연결되면 v1~v5 보상 정의를 실제 클리어·실패 정책에 매핑한다.
8. 다음 확장으로 전체 젬스톤 가중치 드롭 스냅샷, 스킬 실행, 펫 자동 공격을 추가한다.

## 7. 작업 경계와 병합 규칙

- 준영은 `Progression`, `Data`, 경제·저장과 `Contracts`의 진행 데이터만 수정한다.
- 승기는 `Combat`과 전투 전용 HUD/VFX만 수정한다.
- `App/Scenes/Main.unity`, `Contracts`, `ProjectSettings`는 변경 전에 서로 확인한다.
- 새 전투 입력은 `Contracts`에 읽기 전용 데이터와 이벤트를 먼저 추가한 뒤 양쪽을 연결한다.
- 같은 씬과 같은 프리팹을 동시에 수정하지 않는다. 기능별 브랜치와 별도 worktree를 사용한다.
- 병합 전 `git diff --check`, Unity 6000.3.13f1 컴파일, 담당 모듈 Play Mode를 실행한다.

## 8. 테스트 방법

1. Unity Hub에서 **6000.3.13f1**로 프로젝트를 연다.
2. `Assets/CursorHunter/App/Scenes/Main.unity`를 연다.
3. Play를 누르고 테스트 패널에서 일반 Field를 시작한다.
4. 첫 런의 일반 필드가 15초인지, 시간 Stat 후 20초·25초로 늘어나는지 확인한다.
5. 보스 Field는 항상 60초인지 확인한다.
6. 치명타 HUD, 몬스터 HP 바, 정산 재화, 전리품 조각 저장을 확인한다.
7. 특성의 `전체 정보` 팝업에서 Key/Value와 현재 전투 스냅샷을 확인한다.

저장소 검증 스크립트와 Contracts 독립 컴파일은 통과했다. Unity Editor가 같은
프로젝트를 열고 있으면 별도 Batch Mode는 프로젝트 잠금으로 실행되지 않으므로,
전체 Unity 컴파일·Play Mode 검증은 Editor에서 직접 실행하거나 Editor를 닫은 뒤
Batch Mode로 실행한다.

## 9. 남은 작업

- 영구 정산 이벤트 ID 저장
- Combat에서 전체 젬스톤 가중치 풀을 사용하는 드롭 스냅샷
- 실제 보스 공격·파훼·보상 지급
- 스킬 6종 실행과 Dragon Breath 연출
- 펫 자동 공격과 성장
- 테스트 플래그 비활성화 후 150분 밸런스 시뮬레이션

세부 수치·화면 순서·에셋 파일은 [상세 기획서](../cursor-hunter-game-design-v0.0.4.md)를
참조한다. 이 문서는 개발자가 먼저 읽는 요약본이며, 변경 시
[handoff-log.md](handoff-log.md)에 날짜·담당·영향 파일·검증 결과를 누적한다.

## 10. 코드와 상세 기획 수치의 동기화 원장

아래 값은 현재 `TraitCatalog.CreateRuntimeDemo()`와 전투 스냅샷이 복사하는 기준이다.
상세 기획서에 남아 있는 이전 예시 수치보다 이 표와 코드가 우선한다.

### 보스 구간별 접근권

| 구간 | 시간 목표 | Stat 접근 | 젬스톤/스킬 | Monster |
|---|---:|---|---|---|
| 시작 | 0~20분 | 공격력 1~3, 반경 초반, 치명타 5%, 젬 접촉 클릭 | 가넷, 파이어볼 | Monster1 |
| v1 | 20~45분 | 공격력 6~10, 더블, 치명타 10%, 접촉 자동 수집, 보스 공격력 1 | 토파즈 해금 접근, 라이트닝 볼트 | Monster2~5 |
| v2 | 45~80분 | 공격력 16~24, 트리플, 치명타 20%, 자석 | 자수정·사파이어, 프리즈닝·허리케인 | Monster6~9 |
| v3 | 80~120분 | 공격력 35~50, 쿼드, 치명타 30%, 보스 공격력 3 | 다이아몬드, 메테오 | Monster10~13 |
| v4 | 120~150분 | 공격력 70, 자동 무한, 치명타 50~75% | 드래곤 젬, 드래곤 브레스 | Monster14~16 |
| v5 | 150분 전후 | 공격력 100, 전체 반경, 치명타 100%, 보스 공격력 5 | 최종 강화·엔딩 | Monster17~20 |

보스 구간은 구매 접근권이다. 보스가 젬스톤을 자동 해금하지 않는다. 젬스톤은 해당
보스 구간 접근권과 `Stat → 젬 수집` 해금 노드를 모두 만족한 뒤 다음 런부터 보유
목록과 드롭 후보에 추가한다.

### Stat 비용 원장

| 행 | 값 | 실제 비용 순서 | 노드별 결제 재화 순서 |
|---|---|---|---|

선택한 노드 상세의 비용 명칭·보유량은 위 재화 ID에서 직접 가져온다. 따라서 테스트 모드에서
무료 구매를 하더라도 상세 패널에는 원래 필요한 젬스톤 종류와 수량이 표시된다.

### 젬스톤별 역할

| 젬스톤 | 주 획득 구간 | 구매 의미 |
|---|---|---|
| 가넷 | 시작 | 기본 공격력·초반 반경·초반 치명타·15~20초 필드 시간의 입문 재화 |
| 토파즈 | v1 | 더블 클릭, 초기 자동 수집, 공격력·반경 확장, 25~30초 필드 시간 |
| 자수정 | v2 | 트리플 클릭, 중반 반경, 20~30% 치명타, 자석 수집, 35~40초 필드 시간 |
| 사파이어 | v2~v3 | 쿼드 클릭, 1/16~1/8 반경, 50% 치명타, 자석 확대, 45~50초 필드 시간 |
| 다이아몬드 | v3~v4 | 공격력·1/4 반경, 75% 치명타, 55초 필드 시간, 후반 Skill·펫 강화 |
| 드래곤 젬 | v4~v5 | 자동 무한 클릭, 화면 전체 반경·수집, 100% 치명타, 60초 필드 시간, 최종 Skill |

보스 공격력의 표시는 1~5 단계지만, 일반 공격력과 분리된 보스 피해 배율을 사용한다.
실제 전투용 배율은 보스 공격력 단계에 따라 `×1.25 / ×1.60 / ×2.10 / ×2.80 / ×4.00`
초안으로 유지한다.

스킬 해금·강화 비용은 스킬별 전용 젬스톤을 사용한다. 파이어볼은 가넷, 라이트닝 볼트는
토파즈, 프리즈닝은 자수정, 허리케인은 사파이어, 메테오는 다이아몬드, 드래곤 브레스는

현재 전투 모듈의 실제 연결 범위는 기본 공격·치명타·보스 배율과 스냅샷 필드까지다.
6종 스킬의 실제 발동·쿨타임·범위 판정은 승기 Combat 확장 작업이다.

## 11. 화면·UX 기준

### 특성 화면

- 좌측 상단 탭: `스탯 / 스킬 / 몬스터 / 전리품 / 펫`
- 좌측 중단: 현재 해금된 젬스톤 보유량과 확률
- 우측 상단: 현재 적용 특성 요약과 그래프/수치
- 중앙: 카테고리별 한 행의 노드 체인, 노드 사이 커넥터
- 우측 상세: 선택 노드 Key, Value, 현재 값, 다음 값, 필요 재화, `강화/해금`, `노드 초기화`
- 하단: `전체 초기화`, `전체 정보`, 뒤로가기
- 전체 정보: `현재 전투 적용값 → Stat → Skill → Monster → 전리품 → Pet → 젬스톤` 순서의 Key/Value 표
- 화면 폭을 넘는 행은 노드 5개 단위로 개행하고 커넥터를 세로로 이어 붙인다.
- 잠긴 젬스톤·몬스터·전리품은 아이콘·이름·수량을 숨기고 해금 조건만 표시한다.

### 일반 Field

- 현재 해금된 Monster 종이 모두 출현하며 낮은 티어 종은 후반에도 제거하지 않는다.
- 첫 런은 15초, 시간 Stat에 따라 5초 단위로 최대 60초.
- 보스 필드와 달리 상단에는 일반 필드 타이머를 표시한다.
- 처치 시 가넷·해금된 보너스 젬·전리품 조각 후보를 `RunResult`에 기록한다.
- 타이머 종료 시 남은 몬스터는 일괄 제거하고 보상에 포함하지 않는다.
- 몬스터 생성·피격 직후 월드 체력바를 표시한다.
- 우측 상단 `전체 정보` 버튼은 특성 화면과 동일한 오버레이를 연다.

### Boss Field

- 일반 몬스터는 출현하지 않는다.
- 상단에 보스 HP 바와 60초 고정 타이머를 표시한다.
- 보스는 별도 그로기 상태가 없고 공격력·HP·파훼 이벤트로 난도를 만든다.
- 보스 공격력 Stat은 일반 공격력과 분리한다.
- 파훼 성공은 보너스 보상, 실패는 남은 시간 차감으로 처리한다.
- 성공·실패 정산은 `RunSettlementPolicy`를 통해 결과 보상과 분리한다.

### 그래픽·해상도

- 전투 기준 해상도 1920×1080, 최소 지원 1280×720, 16:9 기준.
- Canvas는 기준 해상도에 맞춰 스케일하고 UI 좌표와 전투 좌표를 분리한다.
- `DisplayQualityBootstrap`이 런타임 품질·버퍼를 설정한다.
- 전투 배경은 단일 확대 이미지보다 타일링을 사용한다.
- 아이콘은 GUI-CasualFantasy와 MonsterAsset의 실제 원본을 사용하며, 에셋 매핑은
  [trait-ui-assets.md](trait-ui-assets.md)를 기준으로 한다.

`balanceVersion`을 올린 뒤 다시 비교한다.
