# Cursor Hunter UI 스타일 정책

기준일: 2026-11-17

이 문서는 새 UI를 설계하고 기존 화면을 개편할 때 사용하는 공통 기준이다. 2026-11-15의 ‘연구 화면 하나만을 기준으로 한다’는 시각 정책과 그 이전의 UI 스타일 지침은 이 문서로 대체한다. 과거 캡처·에셋 표·인수인계 로그는 당시 구현을 찾는 기록으로 남긴다. 정산·저장·화면 전환과 같은 동작 계약은 시각 정책의 교체만으로 변경하지 않는다.

기준 화면은 [Main.unity](../../Assets/CursorHunter/App/Scenes/Main.unity)의 `UICanvas/ResearchPrototype_Canvas`, `UICanvas/TraitCard_Canvas`, `UICanvas/Artifact_Canvas` 세 화면이다. `Prototype`이라는 이름은 연구의 개발 경로를 뜻하며 시각 기준에서 제외하는 이유가 아니다. 세 화면의 공통 표현을 우선하고, 화면의 목적에 따라 카드·격자·노드 보드와 팝업의 구성은 달리한다. 각 화면의 과거 구현이나 공급사 데모의 기본 테마는 새 기준이 아니다.

## 세 화면에서 확인한 것

| 화면 | 실제 구성 | 새 정책에 가져올 요소 |
|---|---|---|
| 연구 | 공통 배경 위에 아이콘을 담은 둥근 노드와 연결선을 배치한다. 노드에 올리면 어두운 툴팁에 제목·효과를 표시하고, 해당 연구에 필요한 현재/다음 값과 비용을 보여 준다. 현재 Main 설정의 미완료 노드는 파랑, 최대 랭크는 노랑이며 구매 가능 여부는 별도의 `+`로 표시한다. | 아이콘 중심의 간결한 정보, 단계와 상태의 구분, 가까이 나타나는 상세 정보 |
| 특성 카드 | 공통 배경 위에 남색의 세로 카드 세 장과 왼쪽 보유 아이콘, 상단 레벨·포인트, 하단 공개 버튼을 배치한다. 잠금 상태에는 자물쇠를 보여 주고, 비용 텍스트는 가능/부족 상태에 따라 달라진다. | 넓은 둥근 면, 큰 제목과 읽기 쉬운 설명, 잠금과 선택 상태의 명확한 표현 |
| 유물 | 공통 배경 위에 20개 유물을 격자로 배치한다. 보유 아이콘과 자물쇠를 구분하고, 새 유물에는 `NEW`를 표시한다. 아이콘에 올리면 연구에서 가져온 짙은 툴팁을 보여 준다. | 반복되는 아이콘 셀의 정렬, 보유·미보유·신규 상태 표시, 공통 툴팁 |

세 화면은 [ProgressionUiBackdrop.prefab](../../Assets/CursorHunter/Progression/Prefabs/ProgressionUiBackdrop.prefab)의 푸른 풍경·어두운 색 보정·부유 입자를 공유한다. Main의 상단 메뉴와 하단 액션은 각 화면 바깥의 공통 요소다. 이 문서의 수치와 색은 1920×1080 기준 씬에서 확인한 **참고 사례**이며, 모든 화면에 똑같은 픽셀 크기나 색을 강제하는 토큰 라이브러리가 이미 구현됐다는 뜻은 아니다.

## 공통 시각 규칙

### 배경과 면

- 성장 화면에는 기존 공통 배경을 사용하고, 콘텐츠는 충분히 구분되는 남색 계열의 둥근 패널·카드·셀 위에 놓는다. 배경 삽화와 입자는 분위기를 보조하며 글자나 아이콘의 판독을 방해하지 않는다.
- 정보가 필요한 곳에만 한 단계 더 짙은 둥근 면을 넣어 제목·설명·값을 구분한다. 두꺼운 장식 테두리와 과도한 그림자보다 면의 명도 차이와 여백을 우선한다.
- 별도 맥락의 화면에서는 화면에 맞는 배경을 유지할 수 있다. 특히 결과창은 전투 화면 위에 놓이는 팝업이므로 성장 화면의 풍경 배경을 무조건 가져오지 않는다.
- 툴팁은 둥근 어두운 바깥 면과 더 짙은 내부 정보 면을 사용한다. 필요한 제목과 설명만 남기고, 비용이나 전후 값이 없는 대상에 빈 항목을 억지로 추가하지 않는다.

현재 재사용 후보는 [특성 카드 List](../../Assets/CursorHunter/App/Prefabs/List.prefab), [유물 셀 Stage_Nomal](../../Assets/CursorHunter/App/Prefabs/Stage_Nomal.prefab), [연구 노드](../../Assets/CursorHunter/Progression/Prefabs/ResearchNode.prefab), [재화 표시 CurrencyList](../../Assets/CursorHunter/Progression/Prefabs/CurrencyList.prefab) 및 Main에 배치된 어두운 툴팁이다. 화면의 역할에 맞는 게임 소유 프리팹·Variant 또는 래퍼를 사용하고 공급사 원본을 직접 변경하지 않는다.

### 색과 상태

기본 면은 짙은 남색·청회색, 본문은 흰색 또는 밝은 회백색을 사용한다. 채도가 높은 색은 아이콘과 선택·가능·완료 등 의미 있는 강조에 사용한다. 아래는 현재 화면에서 확인한 예다.

| 용도 | 현재 사례 | 사용 방향 |
|---|---|---|
| 기본 글자 | 흰색, 카드 설명 `#E3ECF8` | 제목·값과 설명을 명도 및 크기로 구분 |
| 연구 노드 | 미완료 `#78C7F2`, 최대 랭크 `#FFC252` | 연구의 진행 상태에 사용. 노란색을 모든 화면의 보편적 성공 색으로 해석하지 않음 |
| 연구 연결·변화 | 연결선 `#21A6F2`, 다음 값의 연한 초록 계열 | 관련 노드와 전후 변화를 빠르게 식별 |
| 특성 공개 비용 | 가능 `#B8F58A`, 부족 `#FF7864` | 가능한 행동과 부족 상태를 텍스트·버튼 상태와 함께 표시 |
| 메뉴·행동 | 선택된 상단 메뉴는 밝은 파랑, 다른 메뉴는 어두운 남색. 보스·사냥 버튼은 별도 강조색 사용 | 화면의 주요 행동과 선택 상태를 구분하되 버튼 색 하나에 고정된 의미를 부여하지 않음 |

색만으로 보유 여부나 가능 여부를 전달하지 않는다. 잠금 아이콘, `NEW`, 수치·라벨, 선택 상태 및 실제 버튼 활성 상태를 함께 사용한다. 재화 아이콘 자체의 색과 형태는 종류 식별을 위해 유지한다.

### 글자와 정보 위계

- TextMesh Pro를 사용한다. 한국어의 기본 인상은 세 화면의 주요 텍스트에 쓰인 [NanumSquareRound-Bold SDF](../../Assets/CursorHunter/UI/font/NanumSquareRound-Bold%20SDF.asset)의 둥글고 굵은 형태를 따른다. 새 UI는 제목·본문·숫자를 같은 화면 안에서 시각적으로 통일한다.
- 화면 제목과 핵심 값은 크게, 섹션 제목과 본문은 그보다 작게, 부가 안내는 한 단계 낮게 배치한다. 특성 화면의 레벨 64, 카드 제목 최대 40, 카드 설명 34는 현재 씬의 사례다. 툴팁은 별도 스케일을 사용하므로 이 숫자를 다른 화면에 그대로 복사하지 않는다.
- 본문·툴팁은 밝은 글자와 배경의 명도 차이를 우선한다. 배경 위의 큰 메뉴·행동 문구에는 기존 화면처럼 어두운 외곽선을 사용할 수 있으며, 굵기는 글자를 가리지 않도록 조정한다. 공유 폰트 에셋·머티리얼을 수정하거나 실행 시 프로젝트 전체 TMP를 일괄 변경하지 않는다.
- 한국어와 영어 등 기존 지역화 키·폰트 폴백을 유지하고, 긴 번역이나 큰 숫자도 잘리거나 겹치지 않도록 공간·줄바꿈·자동 크기를 조정한다. 숫자용 Rubik과 지역별 동적 폰트 등은 기존 기능에서 사용 중이므로 전체를 일괄 교체하지 않는다. 개편하는 화면의 시각 통일과 글리프 지원을 함께 확인한다.
- 퍼센트는 새 연구와 특성 카드의 현재 표현에 맞춰 `10.00%`처럼 소수 둘째 자리까지 표시한다. 표시 형식은 데이터의 계산 정밀도와 분리한다.

### 아이콘·배치·상호작용

- 아이콘은 원래 비율과 선명도를 유지하고 이름·수량과 묶는다. 현재 연구·특성 카드의 아이콘 팩과 젬스톤 카탈로그를 우선 확인하며, 확대해 흐려지는 작은 아이콘을 피한다.
- Main의 공통 `UICanvas`는 Screen Space Overlay, 기준 해상도 1920×1080, Canvas Scaler의 너비/높이 일치값 0.5를 사용한다. 새 화면도 이 좌표계를 출발점으로 삼되 다른 화면 비율에서 잘림·겹침을 확인한다. Main의 EventSystem과 화면 수명주기를 공유한다.
- 반복 셀은 크기와 간격을 일정하게 맞추고, 고정 개수인지 가변 목록인지에 따라 격자·행·스크롤을 선택한다. 툴팁은 대상 근처에 두되 화면 경계 안으로 조정하고 다른 입력을 가로채지 않는다.
- 호버·선택·공개에는 짧은 확대와 반짝임을 사용하되 본문과 클릭 영역을 가리지 않는다. 현재 유물·연구 노드의 호버는 0.14초에 약 1.1배, 보유 특성 아이콘은 0.14초에 1.08배다. 이는 참고값이며 모든 버튼에 같은 연출을 강제하지 않는다.

## 결과창에 적용한 기준

Main의 결과창은 아래 기준으로 구성한다. 젬스톤과 경험치는 `RunResult`의 획득량을 표시하며, 실제 보상 정산은 기존 App 경로에서 처리한다.

1. 일반 결과 화면은 전투 배경을 딤 없이 보여 주고, 중심 결과 패널을 둥근 남색 면으로 구성한다. 유물 획득 시에는 결과 패널 위를 어둡게 덮고 아이콘 뒤에 방사형 빛을 표시한다. 큰 `유물 발견!` 문구와 유물 이름, OK 버튼을 배치한다.
2. 종료·성공·실패·포기를 먼저 읽을 수 있게 제목을 두고, 본문은 넓은 획득 보상 영역으로 구성한다. 기존 전투 기록의 처치 수·전투 시간·총 피해량은 결과창에서 표시하지 않는다. 보상이 없거나 테스트 보상이 지급되지 않는 경우도 문구로 분명히 한다.
3. 획득한 젬스톤만 아이콘·이름·수량의 정렬된 행으로 표시한다. 종류가 하나면 아이콘과 글자를 크게, 종류가 늘면 작게 조절하고 빈 종류의 자리는 남기지 않는다. 획득 경험치는 젬스톤 목록의 맨 아래에 항상 표시하며, 0인 경우에도 표시한다. 긴 이름과 큰 Int64 수량, 한국어·영어에서도 읽을 수 있어야 한다. `+`와 천 단위 구분 등 현재 수량 표현은 유지한다.
4. 하단의 강화/로비와 재도전/다음 단계 등의 버튼은 둥근 면, 굵은 글자와 명확한 활성·비활성 표현으로 구성한다. 버튼 문구와 실제 이동 대상은 일반·보스·포기·테스트 상태에 따라 기존 동작을 따른다.
5. 종료 안내가 끝나고 결과 패널이 나타나는 순간 유물 발견 안내를 함께 시작한다. 결과 패널과 보상 공개는 안내 뒤에서 진행하며 OK를 누르면 유물 안내만 닫히고 결과 행동 버튼이 나타난다. 유물이 없을 때의 보상 공개 중 바로 보기, 종료 안내의 독립된 표시, 연출 감소 설정과 재진입 방지 역시 유지한다.
6. `RunResult`와 저장된 정산 결과가 데이터 기준이다. 화면 효과가 보상이나 경험치·유물의 지급 여부를 결정하지 않는다. 저장 실패 시 결과창을 유지하고 재시도할 수 있어야 하며, 같은 런의 보상이 중복 지급되지 않아야 한다.

## 구현 및 검수

- 새 시각 정책은 개편하는 화면부터 적용한다. 변경 범위 밖 화면의 기존 폰트·재질이나 동작을 한꺼번에 바꾸지 않는다.
- 씬에 이미 배치한 오브젝트와 게임 소유 프리팹을 우선 활용한다. 패널 크기나 배치를 바꿀 때 런타임 코드의 크기 계산·참조·입력 영역이 덮어쓰지 않는지 확인한다. UI 소유권과 참조 방향은 [architecture.md](architecture.md)를 따른다.
- 결과창 작업 시 일반 종료·보스 성공/실패·중도 포기·테스트 결과, 젬스톤 보상 0~6종에 따른 크기와 경험치 0 포함 항상 마지막 행에 표시되는지, 유물 유무, 긴 값, 저장 실패 및 재시도를 검증한다. 실제 Game 뷰에서 한국어/영어와 기준 해상도 및 다른 화면 비율의 가독성·잘림·입력을 확인한다.
- 이 정책은 저장된 Main 씬·프리팹·관련 런타임 코드, Unity 편집 화면의 특성 카드 배치, 기존 격리 실행에서 남긴 연구·특성 화면 캡처를 분석해 작성했다. 새 결과창은 격리 Unity 실행에서 젬스톤 0~6종과 경험치, 한국어·영어, 16:9·4:3 화면을 확인했다. 기준이 된 세 화면의 모든 Play Mode 상태를 새로 시각 검증한 것은 아니다.
