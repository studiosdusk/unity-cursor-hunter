# 연구 맵 에디터 기획서

작성일: 2026-11-13  
상태: 기획 초안. 이 문서의 툴과 데이터 구조는 아직 구현되지 않았다.

## 1. 목표

Unity 에디터에서 연구 노드를 원하는 위치에 배치하고, 노드 SO와 레벨별 비용 및 해금 조건을 설정하여 연구 맵을 제작한다. 작성한 맵은 버전별로 보관하고, 검증한 구성을 원 씬인 `Main.unity`의 연구 UI에 적용한다.

### 확정된 정책

1. 빈 노드를 만든 뒤 기존 연구 노드 SO를 연결한다.
2. 노드 SO가 아이콘, 표시 텍스트 키, 스탯 종류, 레벨별 효과와 최대 레벨을 정의한다.
3. 비용은 맵 툴에서 **배치 노드별, 구매 레벨별**로 설정한다. 각 레벨에서 현재 구현된 젬스톤 6종 중 재화와 수량을 선택하며, 같은 SO를 쓰더라도 위치마다 다르게 정할 수 있다.
4. 노드를 우클릭하여 다른 노드로 화살표를 연결한다. 화살표는 **선행 노드 → 후행 노드** 방향이다.
5. 첫 버전의 선행 노드 충족 조건은 **1레벨 이상 구매**로 고정한다.
6. 맵 구성을 버전별로 관리한다.
7. 별도 시작점 노드는 만들지 않는다. 현재 테스트 맵의 최초 화면에는 중앙 공격력 노드 하나만 나타난다.
8. 기존 연구 구매 기록은 레거시로 보관하며, 새 연구 진행도와 별도로 취급한다. 기존 재화 처리 정책은 이 툴 도입만으로 변경하지 않는다.

## 2. 현재 구현과 변경이 필요한 부분

- 현재 6종의 `ResearchDefinition` SO에 표시 정보, 스탯 효과와 레벨별 비용이 함께 들어 있다. 비용을 배치별로 달리하려면 비용을 SO의 랭크 데이터에서 분리해야 한다.
- 현재 맵은 `Main.unity`의 `ResearchPrototype_Canvas` 아래 씬 오브젝트와 `ResearchTestMap.nodes` 목록으로 구성된다. 노드의 위치, 선행 노드 및 구매 ID는 씬에서 관리한다.
- 구매 랭크는 노드 종류가 아니라 각 배치의 `placementId`로 저장된다. 같은 SO를 두 번 배치하면 두 노드는 별도의 랭크를 갖는다.
- 선행 조건은 나열된 노드 중 1레벨 이상인 노드가 지정된 개수에 도달했는지로 판단한다. 현재 연결 시각화는 단일 `incomingLine` 참조를 사용하므로 여러 선행 연결의 표시를 지원하도록 확장해야 한다.
- 연구 제목과 효과 설명 등은 `Assets/CursorHunter/Data/Authoring/ResearchText.xlsx`가 원본이며 Unity Localization 문자열 테이블을 통해 표시된다. 맵 툴은 이 문구를 별도의 원본으로 복제하지 않는다.
- 현재 구매 검증은 SO의 비용을 다시 확인한다. 툴 도입 시 실제 차감, 구매 권한 검증, 툴팁 비용을 모두 같은 **배치별 비용**에서 읽도록 바꿔야 한다.

## 3. 데이터 구성

### 3.1 연구 노드 SO — 노드 종류

노드의 정체성과 공통 효과를 정의한다. 하나의 SO를 여러 배치가 참조할 수 있다.

| 항목 | 내용 |
|---|---|
| 노드 종류 ID | 노드의 의미를 식별하는 고정 ID. 다른 효과에 재사용하지 않는다. |
| 표시 정보 | 엑셀 문자열 키, 아이콘, 수치 표시 방식. |
| 적용 대상 | 공격력, 범위, 공격 간격, 치명타 확률, 치명타 피해, 보스 피해 등 지원되는 스탯. |
| 레벨별 효과 | 해당 레벨까지의 **누적** 효과. |
| 최대 레벨 | 효과 목록의 길이로 결정한다. |

0레벨은 구매 전 상태이며 연구 효과는 항상 0이다. 현재 지원 범위는 6가지 커서 스탯이다. 스킬·몬스터 등 새로운 효과 유형은 별도 설계 후 확장한다.

### 3.2 맵 배치 노드 — 맵에서의 개별 인스턴스

| 항목 | 내용 |
|---|---|
| 배치 ID | 구매 기록에 사용하는 고유 ID. 자동 생성하고, 위치 변경 시 유지한다. |
| 노드 SO | 이 배치에 사용할 노드 종류. 빈 노드 작성 중에는 비어 있을 수 있다. |
| 위치 | 맵 좌표. |
| 레벨별 비용 | 각 구매 레벨의 재화 ID와 수량. |
| 선행 조건 | 들어오는 연결 목록과 충족되어야 할 연결 수. |

배치 ID와 SO의 종류 ID는 별개다. 동일한 SO를 여러 위치에 넣으면 배치 ID와 비용은 각각 독립적이다. 각 배치의 구매 효과는 기존 방식처럼 합산한다.

SO를 연결하면 최대 레벨에 맞는 비용 행을 만든다. 비용은 명시적으로 설정해야 하며, 미입력은 무료와 구분한다. 무료로 만들려면 수량을 0으로 명시한다. SO 변경이나 최대 레벨 변경 시 비용 행의 추가·삭제를 보여 주고, 입력된 비용을 조용히 버리지 않는다.

### 3.3 연결과 해금

- 연결은 선행 배치 ID와 후행 배치 ID를 참조한다.
- 선행 노드의 구매 레벨이 1 이상이면 해당 연결은 충족이다. 필요 레벨을 연결마다 다르게 설정하는 기능은 첫 버전 범위에 넣지 않는다.
- 후행 노드는 충족된 선행 노드 수가 설정한 필요 개수 이상일 때 해금된다.
- 예: A, B, C가 D의 선행 노드이고 필요 개수가 2이면, A와 B를 각각 1레벨 이상 구매했을 때 D가 해금된다.
- 선행 연결이 없는 노드는 필요 개수가 0이어야 하며 처음부터 해금된다. 선행 연결이 있는 노드의 필요 개수는 1부터 연결 수까지로 제한한다. 따라서 조건 없이 시작하는 노드는 연결 없이 표현한다.
- 자기 자신으로의 연결, 중복 연결, 맵에 없는 노드로의 연결, 순환 연결은 허용하지 않는다.

### 3.4 레벨별 비용 예시

같은 공격력 SO를 참조하더라도 배치마다 별도의 비용을 가진다. 효과는 예시이며 실제 값은 해당 SO를 따른다.

| 구매 레벨 | SO의 누적 효과 | 중앙 공격력 노드 | 바깥쪽 공격력 노드 |
|---|---:|---|---|
| 1 | 공격력 +2 | 가넷 100 | 토파즈 500 |
| 2 | 공격력 +4 | 토파즈 250 | 자수정 1,000 |
| 3 | 공격력 +7 | 사파이어 500 | 다이아몬드 2,000 |

비용은 현재 지원되는 **가넷·토파즈·자수정·사파이어·다이아몬드·드래곤 스톤 6종** 중 하나와 0 이상의 정수 수량으로 설정한다. 각 배치와 구매 레벨에서 서로 다른 젬스톤을 선택할 수 있다. 첫 버전은 구매 레벨당 재화 한 종류를 사용한다. 위 수치는 기능 설명을 위한 예시이며 확정된 밸런스가 아니다.

## 4. 에디터 사용 흐름

### 4.1 맵 열기와 이동

- Unity 메뉴에서 연구 맵 에디터를 열고 편집할 버전을 선택한다.
- 캔버스를 드래그하여 이동하고 휠로 확대·축소한다. 그리드와 스냅, 전체 보기 및 중앙 보기 기능을 제공한다.
- 맵의 노드와 연결을 시각적으로 표시한다. 노드를 선택하면 오른쪽 상세 영역에 설정을 보여 준다.

### 4.2 빈 노드 생성과 SO 주입

1. 캔버스의 빈 곳을 우클릭하고 `빈 노드 생성`을 선택한다.
2. 생성된 노드에 고유 배치 ID를 부여하고, 원하는 위치로 드래그한다.
3. 노드를 선택해 기존 SO를 드래그하거나 목록에서 선택한다.
4. SO의 아이콘, 제목, 적용 스탯, 최대 레벨과 레벨별 효과를 보여 준다.
5. SO가 없는 노드는 편집 상태에서는 유지하되 빈 노드임을 표시한다. 게임 적용과 빌드는 허용하지 않는다.

노드 복제는 SO와 설정을 복사하되 **새 배치 ID**를 부여한다. 맵 버전을 복제할 때는 같은 배치의 구매 기록을 이어갈 수 있도록 기존 배치 ID를 유지한다.

### 4.3 우클릭 연결

1. 선행 노드를 우클릭하고 `연결 시작`을 선택한다.
2. 포인터를 따라 임시 선을 표시하고 후행 노드를 클릭하면 연결한다.
3. 연결 선의 화살표로 해금 방향을 표시한다.
4. 연결 선을 선택해 삭제할 수 있다. 연결 작업은 Esc로 취소한다.
5. 연결이 잘못되었으면 이유를 표시하고 생성하지 않는다.
6. 후행 노드를 선택하면 선행 노드 목록과 필요 개수를 확인하고 수정한다.

### 4.4 비용 편집

- 선택된 배치 노드의 레벨별 효과를 읽기 전용으로 보여 주고, 옆에서 재화와 비용을 설정한다.
- 레벨별 재화와 수량의 직접 입력을 지원한다.
- 모든 레벨에 같은 재화 적용, 선택한 비용 복사·붙여넣기를 지원한다.
- 입력된 효과 수치는 SO에서, 비용은 배치에서 읽는다는 사실을 화면에 구분해 표시한다.

### 4.5 저장과 검증

- 변경사항 저장, 되돌리기·다시 실행, 검증, 씬 적용을 제공한다.
- 검증 결과에서 문제 노드를 선택해 이동할 수 있게 한다.
- 저장되지 않은 변경이 있을 때 버전 전환이나 창을 닫으면 저장·버리기·취소를 선택할 수 있게 한다.

## 5. 씬 배치와 게임 연결

### 제안하는 원본과 작업 흐름

1. **맵 버전 에셋**을 배치·비용·연결의 원본으로 둔다.
2. 에디터가 선택한 버전을 `Main.unity`의 `ResearchPrototype_Canvas` 아래 노드 프리팹과 연결선에 적용한다.
3. 씬에서 노드 오브젝트를 직접 선택해 위치와 외형을 확인하고 조정할 수 있게 한다.
4. 씬에서 변경한 배치 위치 등 맵 데이터에 해당하는 변경은 `씬 변경사항 저장`으로 선택한 버전 에셋에 반영한다.
5. 미저장 씬 변경이 있을 때 다른 버전 적용이나 재생성을 시도하면 충돌을 알리고 저장·버리기·취소를 선택하게 한다. 데이터와 씬이 어느 쪽에서 바뀌었는지 비교할 수 있어야 한다.

맵 데이터에 포함할 항목과 씬 프리팹에서 유지할 외형 설정의 정확한 경계는 구현 설계에서 확정한다. 툴 적용은 기존 씬 오브젝트, 사용자 조정값, 프리팹 연결과 Unity Undo를 고려해야 한다. 적용 중 실패하면 일부 노드만 바뀐 상태로 남기지 않는다.

게임에서는 적용된 배치를 기준으로 툴팁, 비용 차감과 구매 검증이 일치해야 한다. 노드의 상태 색상, 0레벨에서 + 아이콘을 숨기는 정책, 호버 툴팁·확대 연출, 구매 연출, 최대 레벨 반짝임, 맵 이동·확대 기능은 유지한다. 효과음은 설정하지 않는다.

## 6. 버전 관리와 저장 호환

### 6.1 맵 버전

- 버전마다 식별자, 이름, 설명과 배치·연결 구성을 보관한다.
- 기존 버전을 복제해 새 버전을 만들 수 있다. 적용할 게임 버전은 명시적으로 선택한다.
- 저장된 과거 버전을 실수로 덮어쓰지 않도록, 작업 중인 버전과 적용된 버전을 구분한다. 확정된 버전의 수정 방식은 구현 전에 정한다.
- 노드 이동, 비용 변경, 연결 변경은 비교 화면에서 확인할 수 있게 한다.

**SO 참조만 보관하면 과거 버전의 효과까지 보존되지는 않는다.** SO가 수정되면 그 SO를 참조하는 모든 버전의 효과가 바뀔 수 있다. 따라서 과거 효과의 재현이 필요한 시점에는 SO 데이터 스냅샷을 버전에 포함하거나 SO 자체를 버전별로 고정하는 방식을 별도로 결정한다. 텍스트는 엑셀이 현재 원본이므로 과거 문구까지 복원하려면 엑셀의 버전 관리도 별도로 필요하다. 첫 버전에서 맵 구성을 보관한다는 것만으로 효과·문구가 불변이라고 가정하지 않는다.

### 6.2 구매 기록과 호환성

- 구매 기록은 배치 ID와 구매 레벨을 기준으로 유지한다. 위치를 바꾸거나 맵 버전을 복제해도 같은 배치라면 ID를 유지한다.
- 삭제한 ID를 다른 의미의 노드에 재사용하지 않는다. 맵마다 고유 ID가 충돌하지 않도록 생성하고 검증한다.
- 같은 배치 ID의 SO 교체, 구매한 노드 삭제, 최대 레벨 축소, 선행 조건 변경은 기존 진행도에 영향을 줄 수 있으므로 비교 결과에 표시한다.
- 레벨별 비용 변경은 앞으로 구매할 때의 비용에 영향을 준다. 과거에 구매한 비용을 이 구조만으로 자동 환산하거나 환불하지 않는다.
- 현재 저장에는 맵 버전별 마이그레이션과 구매 시 지불 비용 기록이 없다. 플레이어 저장 버전 기록, 삭제 노드 처리, 초과 랭크 처리, 조건 변경 처리, 환불·보상 및 이전 버전으로 되돌릴 때의 정책은 **미확정**이다.
- 미확정 정책이 필요한 변경은 플레이어 저장에 자동 적용하지 않는다. 충돌을 표시하고 마이그레이션 정책이 준비될 때까지 적용을 막는다. 기존 저장을 임의로 초기화하지 않는다.

## 7. 검증 규칙

| 구분 | 오류 또는 확인 사항 |
|---|---|
| 배치 | ID 누락·중복, SO 누락, 맵에 없는 배치 참조 |
| 효과 | SO의 효과 목록 누락, 지원하지 않는 스탯이나 잘못된 누적 효과 |
| 비용 | 최대 레벨과 비용 행 수 불일치, 미입력, 지원하지 않는 재화, 음수 |
| 연결 | 자기 연결, 중복 연결, 누락 참조, 순환, 잘못된 필요 개수 |
| 표시 | 엑셀에 제목·설명 키가 없는 SO |
| 초기 상태 | 선행 연결이 없는 노드 목록을 표시. 현재 테스트 맵에서는 중앙 공격력 노드만 최초 해금인지 확인 |
| 버전·저장 | 기존 배치 ID의 삭제·SO 교체·최대 레벨 축소·선행 조건 변경을 비교하여 호환성 확인 |
| 씬 | 저장되지 않은 씬 변경 또는 맵 데이터와 씬의 불일치 |

작성 중인 빈 노드와 미입력 비용은 편집을 막지 않는다. 적용과 빌드 전 검증에서 오류를 해결해야 한다. 초기 해금 노드가 여러 개인 경우에는 의도적인 맵도 있을 수 있으므로 목록과 경고를 표시하고, 현재 테스트 맵 검수에서는 중앙 공격력 노드 하나인지 별도로 확인한다.

## 8. 첫 구현 범위와 완료 기준

### 첫 구현 범위

- 현재 6종의 연구 SO 선택과 빈 노드 배치.
- 레벨별 배치 비용 편집과 기존 SO 비용의 초기 데이터 전환.
- 우클릭 연결, 연결 삭제, 1레벨 구매 기준 해금 및 필요 선행 개수 설정.
- 맵 버전 생성·복제·저장·비교와 씬 적용.
- 맵 검증 및 오류 표시.
- 기존 연구 UI와 구매·툴팁·전투 효과 연결.
- 현 테스트 맵의 배치 ID와 현재 효과·비용·연결을 보존하여 새 구조로 전환.

### 완료 기준

1. 빈 노드에 SO를 연결하고 위치를 옮긴 뒤 저장·재열기해도 구성이 유지된다.
2. 같은 SO를 두 위치에 넣고 비용을 다르게 설정하면 각각의 툴팁과 실제 구매 차감이 일치한다.
3. 구매 검증은 화면에서 표시한 배치별 비용과 재화를 사용하며, 비용 불일치나 잔액 부족 시 구매하지 않는다.
4. 선행 노드 1레벨 구매 전에는 후행 노드가 잠겨 있고, 필요한 개수를 구매하면 해금된다.
5. 여러 선행 화살표가 표시되고, 삭제·순환·중복 연결 검증이 동작한다.
6. 0레벨 효과는 0이며, 같은 SO를 참조하는 여러 배치의 구매 효과가 각각의 랭크에 따라 합산된다.
7. 버전 복제는 기존 배치 ID를 유지하고 노드 복제는 새 ID를 만든다. 씬 변경 충돌과 저장 영향이 있는 변경을 알린다.
8. 엑셀 문구 수정은 기존 Unity Localization 가져오기 흐름을 통해 툴팁에 반영된다.
9. 기존 테스트 맵의 초기 화면에는 중앙 공격력 노드 하나만 표시되고, 기존 UI 연출이 유지된다.

## 9. 추가 결정이 필요한 사항

1. 확정된 맵 버전의 수정·잠금 정책과 게임에 적용할 버전의 선택 방식.
2. 과거 버전의 SO 효과 및 엑셀 문구까지 재현할 필요가 있는지, 필요하다면 스냅샷을 어떤 단위로 보관할지.
3. 기존 플레이어 저장에 맵 버전을 기록하고, 구매 노드 삭제·SO 교체·최대 레벨 축소·선행 조건 변경을 어떻게 이전할지.
4. 버전 이전 시 과거 구매 비용을 복원하거나 환불해야 하는지. 필요하다면 구매 당시 지불 내역을 별도로 기록해야 한다.
5. 씬 직접 편집으로 허용할 데이터와 프리팹 외형 설정의 경계, 양방향 동기화 충돌 해결 방식.
