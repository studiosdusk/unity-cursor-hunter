# 2026-10-30 · 2시간 30분 목표 장기 밸런스 측정

> 과거 `ui-onboarding-balance` 체크아웃의 기록이다. 게임 시간을 8배로 가속하고 테스트 코드가 게임 내 커서 위치를 대신 움직였으므로 실제 플레이 시간의 증거가 아니다. 현재 `ui-v7-progress`에서는 이 자동 장기 벤치마크를 제거했으며, 아래 수치는 원인 분석용 이력으로만 보존한다.

## 목표

- 목표 전체 플레이 시간: 약 **150분**
- 보스전 시간 가정: **40분**
- 보스전 제외 일반 필드·연구 시간 예산: **110분**

보스전은 실제로 진행하지 않았다. 40분은 플레이타임 목표에서 별도로 가정한 시간이며 이번 측정 결과에 포함하지 않는다.

## 측정 방식과 한계

- 브랜치 `ui-onboarding-balance`, Unity `6000.3.13f1`, 실제 진입 씬 `Assets/CursorHunter/App/Scenes/Main.unity`에서 실행했다.
- PlayMode 테스트가 저장을 잠시 초기화해 새 프로필로 시작하고, 실제 Main 씬의 일반 전투·몬스터 생성·전투 피해·전투 종료 정산·젬스톤 지급·실제 특성 업그레이드 비용을 거쳤다. 테스트가 끝나면 기존 저장을 복원한다.
- 보스전은 실행하지 않았다. 각 단계의 구매 가능한 연구를 마친 뒤에만 특성 화면 우측 테스트 도구로 다음 보스 단계를 열도록 했다. 자원 변환은 사용하지 않았다.
- 게임 시간은 `Time.timeScale=8`로 가속했다. 모든 단계 구매와 메뉴 이동은 테스트 코드가 자동으로 처리했으며 그 시간은 110분 필드 예산에 포함하지 않았다.
- 테스트용 게임 커서는 초당 8 월드 유닛으로 가장 가까운 취약 몬스터를 따라가며 실제 커서 공격 API를 호출했다. **OS 포인터를 움직이지 않고 사람의 마우스 선택·반응·망설임을 모델링하지 않는다.** 따라서 이는 전투·생성·보상·구매 시스템을 연결한 재현 가능한 자동 벤치마크이지, 실제 유저 플레이나 150분 전체의 직접 측정값이 아니다. 자동 커서가 가장 가까운 대상을 계속 노리는 점도 사람 플레이보다 유리한 조건이다.
- 실제 보스 진입·처치 흐름은 이번 측정에서 쓰지 않았고 40분 보스 시간도 재현하지 않았다.

110분을 완전히 끝내는 마지막 일반 런까지 포함해 0.2분 초과했다. 캠페인은 2단계에서 멈췄고, 다음 테스트 보스 단계는 열지 않았다. 2단계 종료 지갑은 가넷 30,625, 토파즈 2,550, 자수정 15, 사파이어·다이아몬드·드래곤 스톤 0이었다. 별도로, 이 표의 단계별 `wallet` 증감은 해당 단계 시작 대비 구매와 보상을 모두 반영한 **순잔액 변화**다.

이 측정에서 110분 비보스 예산 내에 2단계의 구매 가능 연구 9개를 마치지 못했다. 따라서 현재 수급·비용 경로로는 “보스 시간 40분 + 비보스 110분 = 총 150분” 목표를 달성했다고 볼 수 없다. 구매 시간과 사람의 입력 시간은 제외했으며, 자원 변환도 하지 않았으므로 실제 플레이 시간과 정확히 일치한다고 해석하면 안 된다.

Unity Test Runner는 현 단계의 구매 가능 연구가 9개 남은 상태에서 실패로 끝났다. 이는 컴파일·전투 시작 오류가 아니라 **110분 안에 단계 연구를 완료하지 못한 밸런스 목표 미달**이다. 테스트 결과 XML: `/Users/junyoung/Library/Application Support/Dusk Studios/Cursor Hunter/TestResults.xml`.

## 최신 비용 구성에서 중단한 후속 실행

비용을 조정한 뒤 자동 캠페인을 다시 실행했으나, 사용자의 요청에 따라 Unity Test Runner에서 취소하고 PlayMode를 종료했다. 마지막 콘솔 로그는 `tier=4 fieldRuns=90 fieldMinutes=37.5 spendableRemaining=3 sourceDeferred=0`이며, `fieldMinutes`는 해당 단계의 누적 시간이다. 전체 캠페인의 최종 필드 시간이나 110분 목표 달성 여부는 측정되지 않았다. 이 실행은 통과/실패 결과가 아니라 중단된 표본이다.

테스트가 일시적으로 초기화한 저장 프로필은 Unity 테스트 정리 경로로 복원됐고 PlayerPrefs에서 기존 진행 키가 다시 확인됐다. PlayMode 종료 후 Unity는 편집 모드이며 진행 중인 배속 실행은 없다. `BalanceTestKickoff` 임시 메뉴 항목과 이 자동 벤치마크 테스트 코드는 현재 브랜치에서 제거했다.
