# 기획자용 전투 밸런스 창 설계

작성일: 2026-10-25 · 상태: 구현 및 자동 검증 완료

## 1. 목적과 범위

**기획자가 원하는 스탯 값을 자유롭게 설정하고, 그 값을 실제 전투에 실시간으로 적용하는 Unity 에디터 창**을 만든다. 기획자는 직접 플레이하면서 변화를 판단한다.

에디터의 작업은 **값 설정 → 실제 전투 반영 → 플레이 확인 → 최종안의 기본값 저장**이다. 특성 노드와는 연결하지 않는다. 노드 생성·편집, 맵, 선행 관계, 성장 단계, 구매·해금 구성, 후보 효과 변환은 제공하지 않는다.

이번 범위에는 별도 연습 모드, 무제한 세션, A/B 실험 관리, 체감 평가 양식, 통계 대시보드, 프리셋 관리는 포함하지 않는다. 원본 기본값 반영은 `최종 설정 스탯` 탭에서 Save를 눌렀을 때만 수행한다.

네 분류의 Unity 에디터 창과 실제 전투의 실시간 적용 경로를 구현했다. 이전 화면 시안은 현재 명세와 다르다. 검증 결과는 아래 구현 연결 메모에 기록한다.

## 2. 사용 흐름

1. Unity의 Main 씬에서 `Tools > Cursor Hunter > Combat Balance`를 연다.
2. `실시간 테스트` 모드를 선택하고, 네 수치 분류에서 원하는 스탯을 입력한다.
3. 기존 게임의 진입 동작으로 전투를 시작한다. 전투 전에 설정한 값은 시작 시 적용한다.
4. 전투 중에도 값을 바꾼다. 유효한 변경은 같은 전투에 실시간 반영된다.
5. 기획자가 플레이하면서 체감을 확인하고 다시 값을 조절한다.
6. 전투가 끝나거나 메인 메뉴로 돌아가도 마지막 유효 설정을 유지한다. 값을 다시 건드리지 않고 다음 전투를 시작해도 같은 설정이 적용된다.

기존 실제 커서 판정·스킬·몬스터·스폰 시스템에 값을 적용한다. 별도의 전투 모형이나 예측 시뮬레이션을 만들지 않는다.

## 3. 화면과 입력

메뉴는 `Tools > Cursor Hunter > Combat Balance`, 창 이름은 `전투 밸런스`로 한다. 기존 Game 뷰 옆에 도킹해 사용한다.

창 최상단에는 `실시간 테스트`와 `최종 설정 스탯` 두 모드 탭을 배치한다. 각 모드 아래에 `베이스`, `커서 공격`, `스킬`, `몬스터·스폰` 네 수치 분류 탭을 둔다. 모드별로 마지막 선택한 분류를 유지한다. 스킬과 몬스터는 대상을 선택한 뒤 세부 값을 수정한다.

각 항목에는 한글 이름, 단위, 입력값, 실제 적용값을 표시한다. 숫자 입력과 사용 여부 토글을 기본으로 한다. 필요 범위가 분명한 값은 슬라이더를 함께 제공할 수 있다.

커서 범위는 기존 기본 반경을 `1`로 보는 배율로 표시한다. `1.5`는 반경 1.5배, `2`는 반경 2배이며, 직접 입력하거나 `−`/`+` 버튼으로 0.1배씩 조절한다. 최소값은 0.01배다. 실시간 테스트와 최종 설정의 입력값·비교값 모두 같은 배율을 사용한다. 기준은 `GameInformation.BaseAttackRadiusWorldUnits`로 고정하며, Save 후에도 `2`는 계속 `2`로 표시한다. 실제 전투 전달·씬·JSON 저장에는 기존 월드 반경을 사용한다.

상태는 `설정 유지 중·다음 전투에도 적용`, `현재 전투에 적용됨·다음 전투에도 적용`, `입력 오류·직전 값 유지`를 구분한다. 별도 적용 버튼이나 필수 입력 양식은 없다.

## 4. 설정 항목

| 분류 | 설정할 값 |
|---|---|
| 베이스 | 공격력, 치명타 확률, 치명타 피해 배율, 보스 피해 배율, 일반 전투 시간 |
| 커서 공격 | 커서 범위 배율, 같은 대상 재타격 간격, 자동 공격 사용 여부 |
| 스킬 | 7종별 사용 여부와 각 스킬이 실제 지원하는 피해 배율·발동 간격·생성 수·크기·지속 시간·이동 속도·사거리 등 |
| 몬스터·스폰 | 종별 생성 사용 여부, HP, 이동 속도, 크기·피격 영역, 생성 마릿수·간격, 전체 및 각 종에 적용되는 공통 생존 상한, 보상 값 |

현재 유저 강화 경로가 없는 수치라도 실제 전투에서 사용하는 값이면 편집할 수 있다. 예를 들어 화염 방출 피해 배율도 직접 설정한다. 스킬·몬스터 사용 여부는 테스트 설정이며 구매나 해금을 조작하는 기능으로 만들지 않는다.

현재 구현에 없는 연타 수나 전체 스킬 공통 배율 등의 스탯을 새로 동작하는 것처럼 추가하지 않는다. 마법구처럼 발동 주기가 없는 스킬에는 해당 입력을 제공하지 않는다.

## 5. 입력값과 실제 적용값

에디터 입력은 테스트에서 사용할 스탯 값이다. 입력한 공격력이 20이면 실제 전투의 공격력도 20이어야 한다. 유저 진행도에 따른 증가량을 다시 더하지 않는다.

몬스터 HP·속도·크기도 최종 전투값 기준으로 설정한다. 기존 행동 프로필이 입력값에 다시 배율을 곱해 다른 수치가 되지 않게 한다. 스킬 피해는 설정한 공격력과 해당 스킬 피해 배율로 다시 계산하고, 파생된 실제 피해를 읽기 전용으로 표시한다.

기존 Stage의 편성이나 Inspector의 Skill Acquired가 창에서 정한 사용 여부를 덮어쓰지 않게 한다. 테스트 설정의 우선순위를 명확히 해 입력값과 실제 전투값을 일치시킨다.

허용 범위나 정수 반올림으로 값이 보정된다면 보정된 실제 적용값을 보여준다. 적용되지 않은 값을 적용 완료로 표시하지 않는다.

## 6. 실시간 적용 규칙

숫자는 Enter 또는 포커스 해제로 확정하고, 토글은 클릭 즉시, 슬라이더는 조작 중 유효값을 반영한다. 연관된 변경은 검증 후 다음 시뮬레이션 프레임에 함께 적용한다. 재시작은 요구하지 않는다.

| 변경 대상 | 현재 전투 반영 방식 |
|---|---|
| 공격력·치명타·피해 배율 | 다음 유효 타격부터 반영. 활성 스킬의 피해도 재계산하며 과거 피해는 바꾸지 않음 |
| 커서 반경·자동 공격 | 현재 판정과 사용 여부 갱신. 변경 자체로 중복 타격하지 않음 |
| 공격·스킬·스폰 간격 | 남은 진행률을 유지해 대기 시간 재계산. 중복 발동이나 밀린 발동 몰아치기 없음 |
| 스킬 속도·크기·판정·사거리 | 현재 활성 오브젝트에도 갱신. 위치와 이미 맞힌 대상 기록 유지 |
| 스킬 지속 시간·미발생 이벤트 대기 | 남은 비율을 유지해 변경. 이미 끝난 이벤트는 재실행하지 않음 |
| 생성 수 | 같은 전투의 다음 발동·생성부터 적용. 현재 묶음을 소급 재구성하지 않음 |
| 스킬 사용 여부 | 끄면 현재 효과 정리. 켜면 현재 시각부터 정상 첫 발동 대기 시작 |
| 몬스터 최대 HP | 생존 개체의 남은 HP 비율 유지. 신규 개체는 새 최대 HP 사용. 시체를 되살리지 않음 |
| 몬스터 속도·크기·피격 영역 | 현재 생존 개체에도 갱신. 위치·행동 상태 유지 |
| 몬스터 생성 사용 여부 | 끄면 해당 종의 추가 생성 중지. 현재 개체는 유지. 켜면 새 설정의 생성 일정 시작 |
| 생존 상한 | 다음 생성 판정부터 적용. 상한 감소로 기존 개체를 삭제하지 않음 |
| 보상 | 이후 보상 대상 처치부터 적용. 이미 집계한 보상은 바꾸지 않음 |
| 일반 전투 시간 | 경과 시간 유지, 종료 시각 변경. 새 시간이 경과 시간 이하이면 다음 프레임에 종료 |

예를 들어 HP 40/100인 몬스터의 최대 HP를 200으로 바꾸면 80/200이 된다. 이 조정 자체는 피해·처치·보상으로 계산하지 않는다.

창에서 값을 바꾸는 동안 전투를 강제로 재시작하거나 초기화하지 않는다. 일시정지 중에도 값은 갱신할 수 있고, 계속하기 이후 새 값으로 동작한다. 편집창 조작과 Game 뷰 복귀 경로가 공격 입력으로 들어가지 않게 한다.

## 7. 적용 범위와 입력 검증

설정은 해당 Play 세션의 테스트 전투들에 적용하고 실제 유저 저장·지갑·게임 기본 데이터에는 쓰지 않는다. 테스트 전투의 보상은 실제 지갑에 지급하지 않는다. 전투 완료·중도 종료·메인 메뉴 복귀 후에도 마지막 유효 설정을 유지하여 다음 전투에 자동 적용한다. 전투마다 값을 다시 수정할 필요가 없다.

`테스트 설정 해제`, 창 닫기, Play 종료, 대상 교체, Play 중 스크립트 재컴파일 시에만 설정을 해제한다. 창을 닫거나 `테스트 종료 및 설정 해제`를 누르면 활성 테스트를 종료하고 메인 메뉴로 돌아간다.

기존 제약인 Int64 공격력·HP·보상, 커서 간격 최소 0.05초, 확률 0~100%, 치명타 피해 최소 1배, 스킬별 최소 간격·풀 한도, 일반 전투 15~30초, 전체 생존 수 최대 80을 유지한다. 각 종에 적용되는 공통 상한은 하나의 값이며 전체 상한을 넘지 않는다.

잘못된 입력이나 적용 실패는 해당 행에 표시하고 직전 유효값으로 전투를 유지한다. 변경 실패 때문에 일부 값만 적용하거나 전투를 초기화하지 않는다.

## 8. 완료 기준

1. 네 분류에서 원하는 값을 설정해 실제 전투를 시작할 수 있다.
2. 전투 중 변경이 재시작 없이 현재 커서·활성 스킬·몬스터·스폰에 정해진 시점부터 반영된다.
3. 입력 공격력 20이 실제 공격력 20으로 적용되고, 저장된 증가량이 중복 합산되지 않는다.
4. 몬스터 최종값과 사용 여부도 행동 프로필·Stage·Inspector에 덮어써지지 않는다.
5. 입력값과 실제 적용값이 일치하며 오류 시 직전 유효값을 유지한다.
6. 실시간 테스트 설정과 종료는 실제 유저 저장·지갑·원본 데이터를 변경하지 않는다. 원본 기본값은 최종 탭의 Save에서만 변경한다.
7. 에디터에 특성 노드 생성·편집·맵·성장 경로와 연결되는 기능이나 데이터가 없다.
8. 전투 완료와 중도 종료 후에도 추가 편집 없이 같은 최종값으로 다음 전투를 시작할 수 있다. 명시적으로 설정을 해제하면 다음 전투부터 일반 기본값을 사용한다. 현재 Main의 특성 연동은 해제되어 있어 구매한 특성은 합산하지 않는다.

## 9. 구현 연결 메모

App이 에디터의 테스트 설정을 받아 Combat의 실제 실행값에 전달한다. Combat이 에디터 창이나 유저 저장을 직접 참조하지 않게 한다. 표시값과 실제 적용값은 같은 계산 경로를 사용한다.

`CombatBalanceWindow`가 입력을 검증한 뒤 `HuntManager`의 임시 테스트 설정으로 전달한다. 기존 전투 시작 동작은 테스트 설정이 있으면 진행도 증가량을 거치지 않고 최종값을 사용한다. 전투 중에는 `CombatRunController`와 `MonsterSpawner`가 활성 스킬·기존 몬스터·생성 일정을 갱신한다. `RunCoordinator`는 해당 전투의 정산 정책을 Discard로 고정한다.

설정은 메모리와 Edit → Play 전환용 Unity SessionState에만 보관한다. 씬·프리팹·JSON·유저 저장으로 내보내지 않는다. Play 중 스크립트 재컴파일 시 현재 테스트를 종료하며, 다른 HuntManager로 대상을 바꾸면 이전 테스트 설정을 해제한다.

## 10. 검증 결과

Unity 6000.3.13f1의 격리 복제 프로젝트에서 전체 EditMode 153개와 PlayMode 24개를 통과했다. 복제본의 회사·제품 이름을 분리해 실제 유저 PlayerPrefs에 접근하지 않았다.

추가 검증은 최종값과 Int64 복사, 시간 단축 시 경과 시간 유지, 7종 스킬 입력 검증·사용 여부 우선순위, 활성 토네이도·화염 커서·마법구 갱신, HP 비율·Int64 경계, 생성 일정·종별 사용 여부·잘못된 변경의 원자성, Main 실제 전투 연결·정산 폐기·설정 해제 및 메인 메뉴 복귀를 포함한다. 전투 간 설정 유지 수정 후 PlayMode 23개를 재검증했으며, 추가 편집 없이 완료 후 재시작·메뉴 복귀 후 재시작하는 3회 연속 전투에서 커서·스킬·몬스터 설정이 유지되는지 확인했다. Python 데이터·협업 검사와 공백 검사도 통과했다.

실제 Game 뷰에서 기획자가 느끼는 조작감과 창 배치의 수동 시각 검증은 별도로 진행한다.

## 11. 최종 설정 스탯과 Save

1. `실시간 테스트` 모드의 네 수치 분류에서 전투를 확인한다.
2. `최종 설정 스탯`에서 `현재 테스트값 가져오기`로 수치를 복사하거나 직접 최종안을 수정한다. 처음 열 때 현재 테스트 입력값을 가져온다.
3. 최종안과 `저장된 기본값`을 비교한다. 최종안 편집은 현재 전투에 실시간 적용하지 않는다.
4. `Save · 게임 기본값 저장`을 누르면 전체 입력을 검증하고 원본에 저장한다. 성공 표시와 저장된 기본값을 갱신한다. 잘못된 입력·저장 준비 중 외부 변경은 전체 저장을 거부한다.

| 저장 범위 | 실제 원본 |
|---|---|
| 공격력·반경·재타격 간격·자동 공격·치명타·보스 배율 | 선택한 Main 씬의 PlayerCombatStatsDefaults |
| 일반 전투 시간 | Main의 HuntManager와 game-data.en.json |
| 7종 스킬 수치 | Main의 각 스킬 BaseStat 프리팹 인스턴스 override |
| 몬스터 HP·속도·시각 크기·피격 영역·생성 간격·기본 생성 수·보상 | 종별 MonsterDefinition의 BaseStats |
| 전체·종별 공통 생존 상한 | game-data.en.json의 rules |

게임 정보 JSON의 몬스터 HP·간격·보상 표시값과 한국어 참고 문서도 함께 동기화한다. 몬스터 수치는 입력한 최종값을 새 기본값으로 저장하며, 해당 Definition의 `baseStatsAreFinalValues`를 켜 프로필의 수치 배율을 다시 곱하지 않는다. 프로필의 이동 모드와 특수 능력은 유지한다. Int64 HP를 직접 전달하므로 101처럼 프로필에서 역산할 수 없는 값과 큰 정수도 보존한다.

스킬 사용 여부·몬스터 생성 토글·구매/해금·Stage 편성·유저 지갑·특성 노드는 저장하지 않는다. 기본 생성 수는 Definition의 packSize이며, 일반 전투에서는 Stage 생산 옵션이 추가될 수 있다. 현재 Main은 특성 연동이 해제되어 구매 보너스·강화 증가량을 더하지 않는다. 연동을 다시 켠 경우에만 기존 특성 증가량을 추가한다.

Play 중에도 저장할 수 있다. 런타임 오브젝트·위치·타이머·풀 상태나 씬 전체를 저장하지 않고 지정한 기본 필드만 변경한다. 원본·메타 GUID·다른 씬 편집값을 보존한다. Play 종료 후 복원된 편집 씬에도 저장한 필드만 동기화해 옛 값으로 되돌아가지 않게 한다.

기본값 조회와 저장 준비에서는 Main 씬을 추가 로드하지 않는다. `CombatBalanceSceneSource`가 원본 YAML과 스킬 프리팹의 숫자 필드 및 인스턴스 오버라이드만 읽는다. 검증용 컴포넌트는 조명·카메라·외형·객체 참조가 없는 비활성 임시 객체로 만들고 즉시 정리한다. 기존 Global Light가 켜진 상황과 Main 실제 전투 중에도 중복 조명 로그가 발생하지 않고 조명·런 ID·경과 시간·실시간 스탯이 보존되는지 회귀 테스트했다.

최종안은 Play 종료 후에도 창에 남으며 `저장된 기본값 불러오기`로 원본을 다시 읽을 수 있다. 테스트 override는 별도로 유지된다. 저장한 기본값으로 일반 전투를 확인하려면 `테스트 설정 해제`를 누른다.

저장 검증은 임시 폴더에 복제한 Main 씬·11종 Definition·영어 JSON으로 실행했다. 전체 저장 후 다시 import하여 공격력·HP·보상의 Int64, 7종 스킬 기본값, 프로필 HP 배율 2.5인 종의 HP 101, 씬 비수치·프리팹 참조·메타 GUID·JSON의 해금/업그레이드/생산 정책 보존을 확인했다. 잘못된 입력과 두 파일 중 하나의 외부 변경 시 전체 저장 거부도 확인했다. 실제 프로젝트의 기본 수치는 구현/테스트 과정에서 변경하지 않았다.
