# BabyDragon 펫 스킬 기획·구현

상태: 1차 구현 완료, Main 전투 화면의 크기·정렬·이펙트 확인 대기 · 2026-10-19

BabyDragon은 일곱 번째 자동 스킬로 취급한다. 해금한 런에서 한 마리가 등장하고, 가까운 적을 스스로 찾아 이동·공격한다. 기존 `skill.cursorAura`의 커서 중심 범위 공격이나 v0.0.4의 펫 노드 수치를 이어받지 않는다. 전투 피해·처치·보상과 런 수명주기는 현재 여섯 스킬이 사용하는 경로를 따른다.

## 현재 코드에서 이어받을 구조

| 단계 | 현재 경로 | BabyDragon 적용 |
|---|---|---|
| 해금과 저장 | `progression-config.en.json` 구매 노드 → `GameInformationBuilder` → `GameInformation.skills` | 고정 ID `skill.pet_baby_dragon`의 해금 노드 추가. 구매 결과는 다음 런부터 적용 |
| 런 시작 | `HuntManager` → `RunCoordinator.Start` → `CombatRunController.PrepareRun/ConfigureSkills/CommitStart` | `IRunSkillController` 구현체가 해금 스냅샷을 받고 한 마리의 런타임 스탯을 고정 |
| 개별 실행 | 각 스킬 컨트롤러가 `CombatRunController.ElapsedSeconds`로 동작 | 펫의 탐색·이동·공격 시계를 펫 컨트롤러가 소유 |
| 피해와 정산 | `CombatRunController.TryApplySkillDamage` | 펫도 `CombatDamageSource.Skill`로 피해를 전달. 치명타·보스 배율·처치·보상·DPS는 공통 경로 사용 |
| 종료와 재사용 | `StopSkill`, `RunId`, 일시정지/만료 검사 | 펫을 비활성화하고 대상·공격 예약·연출 상태를 초기화 |

`Combat`은 `App`의 커서 컨트롤러 타입이나 `Progression` 저장소를 참조하지 않는다. Main 씬에서 `Transform` 커서 앵커만 펫 컨트롤러에 연결하고, Sandbox에서는 시험용 앵커를 사용한다. Main의 `cursor_image`는 기본 마우스 모드에 숨겨져 있어도 위치가 갱신되며, 펫은 그 월드 좌표를 따른다.

## 게임 동작

1. 펫 스킬이 잠겨 있으면 BabyDragon은 전투 중에도 보이지 않는다. 해금되어 있으면 전투 시계가 시작된 직후 커서 옆에 한 마리가 나타난다. 보스전도 같은 런 수명주기를 쓰며, 보스 대상의 등록 경로는 실제 보스 전투를 연결할 때 확인한다.
2. 펫은 자신의 탐지 반경 안에서 현재 런에 등록되고 공격 가능한 적 중 가장 가까운 대상을 선택한다. 대상을 잡은 뒤에는 죽거나, 무적이 되거나, 추적 범위를 벗어날 때까지 유지한다.
3. 대상이 공격 사거리 밖이면 이동 속도에 따라 접근한다. 사거리 안에서는 멈춰서 단일 대상을 공격한다. 대상을 잃으면 커서 근처 대기 위치로 돌아간다. 커서에서 너무 멀리 떨어진 적은 추적하지 않는다.
4. 공격 주기가 준비되고 대상이 사거리 안에 있으면 Spine `Attack`을 한 번 재생한다. 실제 피해 시각은 런 전투 시계로 예약하며, 명중 순간 대상의 런 ID·활성 상태·사거리를 다시 확인한다. Spine 이벤트 콜백으로 피해를 주지 않아 한 공격의 피해는 한 번만 적용한다.
5. 펫은 적의 피격 대상이 아니며 적 이동과 커서 공격을 가로막지 않는다. 한 번의 공격은 한 대상에게 한 번만 적용한다.

### 첫 플레이테스트용 기본값

| 스탯 | 초안 | 의미 |
|---|---:|---|
| 피해 배율 | 플레이어 런 시작 공격력 ×0.5 | `SkillStatMath.ScaleDamage`로 정수 피해를 만들고 공통 피해 경로에 전달 |
| 공격 간격 | 1.2초 | 공격 속도 약 0.83회/초. 한 필드에 하나의 공격 시계 |
| 이동 속도 | 초당 4 월드 단위 | 목표 추적과 커서 복귀에 공통 사용 |
| 탐지 반경 | 8 월드 단위 | 펫 위치에서 새 대상을 찾는 거리 |
| 공격 사거리 | 1.5 월드 단위 | 적의 피격 영역에서 가장 가까운 지점까지의 거리 |
| 커서 추적 한계 | 10 월드 단위 | 이 범위 밖으로 이어지는 적 추적을 중단 |
| 대기 거리 | 커서에서 약 1.5 월드 단위 | 대상이 없을 때 돌아올 위치 |

이 숫자는 성장 수치가 아니라 `PetSkillController` 프리팹과 Main 인스턴스 Inspector의 **첫 플레이테스트용 BaseStat**이다. 전투 진입 때 `PetRuntimeStat`을 한 번 계산한다. 현재 성장 노드는 가넷 40개로 구매하는 해금 하나뿐이며, 피해 배율·공격 간격·이동 속도·탐지 및 공격 사거리의 구매 강화 단계는 첫 플레이테스트 뒤 결정한다. 런 스냅샷의 해당 증가량은 이미 적용 가능하다. 공격 간격은 Spine 공격 클립 길이 0.5초보다 짧아지지 않게 제한한다.

## BabyDragon 애니메이션과 씬 에셋

`Export/BabyDragon.json`에는 `Idle`, `Walk`, `Attack`, `Busking`이 있다. `Attack` 길이는 0.5초이고 `Attack` 이벤트는 약 0.167초 지점이다. 대기·이동·공격 상태에 각각 `Idle`·`Walk`·`Attack`을 사용한다. `Busking`은 전투 동작에 쓰지 않는다. 일시정지에는 Spine 재생도 멈추며, 재개할 때 현재 상태를 이어간다.

Main에 배치된 `Spine GameObject (BabyDragon) (1)`은 씬 최상위의 프리팹 인스턴스다. 자식으로 사용자가 배치한 `MagicCircle1_Green` 고리 프리팹 인스턴스가 있다. 이 **씬 인스턴스와 자식 고리를 펫 전투 개체로 사용**한다. `PetSkillController`가 씬 인스턴스를 직접 참조해 해금 전과 런 종료 후에 숨기고, 전투 시작 때 커서 옆으로 옮겨 활성화한다. 공급사 프리팹과 사용자가 조정한 씬 인스턴스를 재구성하거나 덮어쓰지 않는다.

`PetSkillController` 프리팹 인스턴스는 Main의 `CombatManager` 아래에 한 개 둔다. 컨트롤러는 Main에 있는 펫 한 마리를 참조해 런마다 재사용한다. 매 공격마다 펫을 생성하지 않는다. `Combat` asmdef에는 `spine-unity`와 `spine-csharp` 어셈블리 참조를 추가했다.

공격 명중 연출은 사용자가 지정한 `Assets/DownLoadAssets/Casual_VFX/Cartoon Casual VFX Pack/Prefabs/Explosion/Explosion_Effect_Blue.prefab`을 쓴다. 피해가 확정되는 순간 적의 피격 지점에서 한 번 재생한다. 파티클은 시각 연출이고 피해 판정은 기존 `TryApplySkillDamage` 경로가 담당한다. 이 원본 프리팹의 루트 스케일은 3이고 여섯 ParticleSystem이 모두 반복·자동 재생으로 설정되어 있다. 컨트롤러는 복제한 파티클의 반복을 끄고 방출을 0.3초 뒤 멈춘다. 최대 8개를 런 준비 때 미리 만들고, 효과가 끝나면 풀로 돌린다. 풀이 모두 사용 중이면 해당 타격의 VFX만 생략한다. 공급사 원본과 사용자가 조정한 설정은 건드리지 않는다.

## 전투 중 아군 식별

BabyDragon은 청록색이며 적 몬스터도 여러 색의 귀여운 캐릭터로 구성된다. 캐릭터 색만으로 편을 구분하지 않고, 한 마리만 등장하는 펫에 일관된 **형태·위치·색** 신호를 준다.

| 방법 | 효과 | 적용 판단 |
|---|---|---|
| 머리 위 작은 별 배지 | 겹쳐 보일 때도 아군임을 형태로 식별 | 고리만으로 구분이 어려울 때 추가 |
| 발밑 얇은 아군 고리 | 이동 중 펫의 위치를 계속 추적 | Main의 BabyDragon 자식 `MagicCircle1_Green`을 그대로 사용 |
| 커서 근처의 일정한 대기 위치 | 대상이 없을 때 펫이 어디 있는지 예측 가능 | 기존 대기·복귀 동작에 반영 |
| 약한 Spine 외곽광 | 적과 겹쳤을 때 실루엣 보강 | 실제 전투 화면에서 기본 표식만으로 부족할 때 추가. 게임 소유 머티리얼 사용 |
| 등장·명중 순간의 아군색 VFX | 소환 및 펫 공격의 출처를 알림 | 지속 광원 대신 짧은 연출로 추가 가능 |

**첫 구현 기준:** 기존 자식 고리를 펫과 함께 이동·표시하고, 대기 시 커서 옆의 일정한 위치로 돌아오게 한다. 고리는 공격·이동 애니메이션 중에도 읽혀야 한다. 녹색 필드와 몬스터가 겹치는 실제 전투 장면에서 고리의 대비·크기·정렬 순서를 확인하고, 부족할 때 머리 위 배지나 약한 외곽광을 추가한다.

펫 루트에는 런 준비 때 `SortingGroup`을 한 번 구성한다. BabyDragon과 자식 고리가 같은 그룹으로 몬스터 사이에 섞인다. 몬스터와 같은 Default Sorting Layer 및 화면 Y 기반 0~199 Sorting Order를 사용하며, 아래쪽에 있을수록 앞에 보인다. 등장·이동 직후에만 갱신하고, Y가 그대로이면 카메라 좌표 계산을 건너뛰며, 계산한 순서가 같으면 렌더러 값을 다시 쓰지 않는다. 타격 이펙트 200과 체력바 250은 그 앞에 남는다.

## 데이터와 코드 변경 범위

1. **Contracts/Data:** `skill.pet_baby_dragon`을 알려진 스킬과 허용 스탯 ID에 추가하고, `GameInformation`의 7번째 스킬을 검증한다. 실행 JSON·스키마·예제·한국어 참고본·검증 스크립트의 스킬 목록을 함께 확장했다. 기존 여섯 ID와 순서는 유지한다.
2. **Progression:** `stat.attack.01` 이후 가넷 40개, 보스 0단계의 해금 노드 하나를 추가했다. 기존 `skill.cursorAura` 구매 ID를 새 펫에 부여하지 않는다.
3. **Combat:** `PetSkillController : IRunSkillController`, `PetBaseStat`, `PetRuntimeStat`을 추가했다. 대상 목록은 `MonsterCombatTarget.CollectActiveForRun`으로 재사용하고, 공격 사거리는 적의 피격 영역 기준으로 측정한다. 파란 폭발은 컨트롤러의 풀에서 한 번 재생·회수한다.
4. **App/씬:** Main의 커서 앵커와 기존 BabyDragon 씬 인스턴스를 새 컨트롤러에 연결했다. 이미 배치한 고리 자식을 보존하고, 성장 화면의 스킬 노드에 BabyDragon 아이콘을 배정했다.
5. **문서:** `docs/skill-design.md`의 공통 자동 스킬 규칙을 따른다. v0.0.4의 자동 펫과 `skill.cursorAura`는 과거 기록이다.

## 검증 기준

- 잠금 상태와 해금 상태에서 전투 입장·종료를 반복해 펫 표시가 정확하고 중복 인스턴스가 없는지 확인한다.
- 가까운 적 선택, 대상 소멸·무적·추적 한계, 공격 사거리 경계, 여러 콜라이더를 가진 같은 적의 단일 피격을 확인한다.
- 공격 간격과 피해가 런 시작 스탯으로 고정되고, 펫 피해가 기존 치명타·보스 배율·처치·보상·DPS 경로에 한 번만 집계되는지 확인한다.
- 일시정지·시간 만료·포기·재시작과 이전 `RunId`의 늦은 명중이 피해를 만들지 않는지 확인한다.
- CombatSandbox의 고정 스냅샷으로 동작을 검증한 뒤 Main에서 Spine 애니메이션·정렬·실제 크기·커서 추종을 확인한다.
- 기존 자식 고리가 펫과 함께 나타나고 사라지는지, 파란 폭발이 매 명중마다 한 번만 재생되고 반복 잔류·누적되지 않는지 확인한다.

### 현재 검증

- 격리된 Unity 6000.3.13f1 복제본에서 EditMode 전체 104개와 PlayMode 전체 19개가 통과했다. CombatSandbox 테스트는 잠금·해금, 펫과 고리 표시, 이동·단일 명중, 이펙트 반복 해제, 일시정지·런 포기를 검사한다.
- Main 씬 PlayMode 테스트는 기존 BabyDragon·고리 표시와 Spine 컴포넌트, 파란 폭발 프리팹의 풀 준비, 몬스터와 같은 Sorting Order, 런 종료 후 숨김을 검사한다. Sandbox PlayMode에서는 Y 이동 때 순서 변경과 X 이동만 있을 때 카메라 계산 생략을 검사한다. EditMode는 펫 런타임 수치·허용 증가량·구매 스냅샷을 검사한다.
- Main의 실제 전투 화면에서 Spine 크기·정렬·고리 대비·파란 폭발 크기와 보스전 외형은 아직 플레이테스트가 필요하다.
