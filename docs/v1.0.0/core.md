### 이번 결과물

- 기존 클릭 전투·보스5종·일반6종·스킬5종·잼 스톤5종을 유지한다.
- Keep on Mining의 영구 성장·다음 강화가 보이는 트리·후속 자동화에서 플레이 리듬을 참고한다.
- 후반 공격력 1레벨의 긴 대기 시간을 부분 강화로 나누되 총 비용과 최종 공격력은 유지한다.
- 48개 화면/상태를 첫 실행→일반 사냥→성장→보스→엔딩→설정·예외 순으로 설계한다.
- PDF의 화면 아래 이동 링크는 검토용이다. 실제 게임 버튼과 자동 전이는 화면·명세에서 구분한다. PDF 내 이동이 게임 로직 구현을 뜻하지 않는다.

### 결정의 상태

사용자 확정: 약2시간 엔딩, 강한 인플레이션, 일반 몬스터 종류 누적, 대량 처치, 성장 후 보스 돌파, Stat/Skill/Monster 자유 분기, 좌상단 탭·좌중단 재화·우상단 특성 요약. 이미 확정된 보스 실패 무보상과 클릭 입력도 유지한다.

이번 제안: Windows·한국어/영어·마우스/키보드 출시, Steam Cloud·도전과제12개, 부분 강화, 아래 저장·튜토리얼 상세. 별도 회신 전에는 승인 완료로 취급하지 않는다. 문서 버전v1.0.0은 출시 목표이지 이미 배포했다는 의미가 아니다.

읽기: 앞부분은 출시 검토와 규칙 원장, 뒤의 S01~S48은 화면별 진입 조건·정보·버튼·복귀·예외다. 숫자·아트는 기획용 예시이며 실제 제품 스크린샷이 아니다.

### 기존 구조 유지와 대안

추천은 기존 루프를 유지하고 작은 강화 단위와 명확한 다음 목표를 추가하는 안이다. 새 장비 제작·랜덤 특성 카드·별도 광산을 추가하면 성장 선택지는 늘지만 약2시간 목표, UI, 저장, 밸런스 검증 범위도 커진다. v1에서는 추가하지 않는다.

장점: 기존 전투와 비용표를 재사용하고 성장 빈도·화면 완성도를 높일 수 있다. 단점: 부분 강화의 UI·저장 필드가 추가된다. 부작용: 자동화를 먼저 구입한 빌드가 약할 수 있으므로 한 가지 구매 순서를 강제하지 말고 실측으로 비용을 조정한다.

완료 조건은 ‘문서에 미정이 없다’가 아니라 ‘출시 범위가 정해지고, 필수 상태가 설계되고, 정한 플레이 경험을 빌드로 검증했다’이다. 실제 검증 전에는 출시 가능 판정을 내리지 않는다.

## A02. Keep on Mining에서 참고할 느낌

공식 Steam 소개에서 확인한 내용: 커서를 바위 위에 올리면 채굴이 작동하고, 재료를 모아 영구 강화 트리와 곡괭이 제작에 사용한다. 랜덤 특성 카드와 나중에 열리는 자동 광산도 소개된다. 이 문장은 소개 자료 요약이며 실제 게임을 이번 작업에서 직접 플레이한 결과는 아니다.

출처: [Keep on Mining 공식 Steam 페이지](https://store.steampowered.com/app/3769130/Keep_on_Mining/) / 확인일2026-09-09. 사용자가 제공한 트리 스크린샷은 고정 메뉴·재화·연결 노드의 배치 참고 자료로 사용했다.

| 참고하는 경험 | Cursor Hunter에 적용할 해석 | v1에서 유지할 차이 |
| --- | --- | --- |
| 커서가 작업의 중심 | 몬스터 군집 위로 커서를 옮기는 짧은 이동 | 최초는 좌클릭, 자동은 특성 해금 |
| 영구 성장과 큰 트리 | 현재 가진 것과 다음 몇 개의 선택을 한 화면에 | Stat/Skill/Monster, 배타 선택 없음 |
| 성장 뒤 빨라지는 처리 | 큰 반경·다중 타격·자동화로 과거 적을 순간 처치 | 보스는 별도60초 화력·파훼 관문 |
| 재화가 다음 행동을 만듦 | 부족 보석과 얻을 수 있는 몬스터·보스 안내 | 익숙한 보석5종, 확정 드롭 |
| 후속 자동화 | 자동10→30묶음으로 손의 부담을 줄임 | 방치 수입·별도 광산·재료 가공 없음 |

### 플레이 리듬의 제작 지침 (우리 게임의 목표)

- 조준→충돌→파편→보석 흡수는0.1~0.65초에 읽혀야 한다. 적의 밀도와 색을 바꾸며 후반 물량 증가를 보여준다.
- 구매 즉시 숫자와 노드가 바뀌고 다음 사냥에서 효과를 체감한다. 메뉴 복귀와 구매에 불필요한 확인 팝업을 두지 않는다.
- 기본60초 런은 유지하지만 정산에서Space 한 번으로 다음 사냥. 이동 중인 보석 연출 때문에 정산 버튼을 늦추지 않는다.
- 짙은 남색 트리 배경, 밝은 연결선, 읽기 쉬운 사각 노드, 좌측 재화가 시각 방향이다. 몬스터·아이콘·배경·음원은 Cursor Hunter용으로 제작한다.

게임의 모든 기능을 따라 넣는 것이 아니라, 손이 가볍고 강화가 자주 보이며 나중에는 화면의 무리가 빠르게 정리되는 경험을 목표로 한다.

## A04. 강화 빈도 패치 제안

기존 후반 마지막 공격력 비용: L19→20은16,607,532가넷, L24→25는664,301,250가넷. 일반 공급의60%를 번다고 가정하면 각각 약10.08분·9.17분이다. 이 수입은 실제 측정값이 아니지만, 긴 구매 간격이 생길 수 있다는 수치 근거는 있다.

### 총 비용·최종 화력은 유지하고 나눠 구매

- L0~4의 다음 노드: 기존처럼1회 구매. L5~9: 노드당5회 부분 강화. L10~29: 노드당10회 부분 강화.
- 다음 완성 노드의 총 비용을C, 부분 횟수를s라 하면 divmod(C,s)의 몫을 기본 부분 비용으로 사용하고, 나머지r회에만1가넷 추가한다. 합계는 정확히C이다.
- 현재 완성 레벨L과 부분 횟수q에서 연속 성장 위치u=L+q/s를 사용한다. 기존 구간 지수 보간식에u를 넣어A를 반올림한다. q=s이면L을1올리고q=0으로 정규화한다.
- 구매할 때마다 피해량이 증가한다. 낮은 단계 반올림으로 증가가0인 경우를 검산해 막는다. 완성 노드의 선행선을 지나려면 그 노드 부분 강화를 끝내야 한다.
- 비용·HP·최대 공격력 기준점은 기존표와 동일. 마지막 후반 부분 구매 간격은 위 가정에서 약60.5초·55.0초로 줄어든다.

### UI 예시

‘공격력 노드12 / 강화3 of10 / 현재→다음 피해량’처럼 완성 레벨·부분 진척·실제 다음 피해를 분리한다. 예시 피해는 선택 노드에서 공식으로 계산하며 고정 문구로 저장하지 않는다. 한 번 누르면 부분1회, Shift+구매는 현재 노드 완성에 필요한 남은 부분만 미리 총비용을 표시하고 일괄 구매한다. 다른 노드로 자동 넘어가지 않는다.

### 검증과 한계

기준 빌드의 누적 비용은 유지하지만 힘이 중간에도 증가해 실제 수입과 엔딩 시간은 빨라질 수 있다. 공격 우선·범위/물량 우선·재화/스킬 우선 세 경로에서 첫 엔딩110~130분을 목표로 검증한다. 공격력만 또는 경제만 끝까지 사는 모든 단일 가지 빌드의 클리어를 보장한다는 뜻은 아니다. 선택 순서를 되돌릴 수 없어서 진행이 막히는 상태가 나오면 가격·수입을 조정한다.

## A05. 공통 UX · 전투와 정산

- 기준1920×1080, 최소1280×720, 전투16:9 영역 고정. 타이머좌상단, 보석우상단, 보스HP는두번째행. 특성만 보석좌중단·탭좌상단·요약우상단이다.
- 실게임 본문 최소18px, 주요 수치24px, 클릭 영역 최소48px. UI100~150%에서 목록은 스크롤한다. PDF 와이어프레임은 축소도이며 실제 폰트 크기가 아니다.
- 입력 우선순위: 시스템 모달 > 메뉴 > 파훼 표식 > 전투. 화면전환·모달해제의 클릭은 다음 화면에 전달하지 않는다.
- 수동은 좌클릭 누름1회, 홀드/이동 자체로 피해 없음. 겹친 살아 있는 적 모두에게A×M 타격 묶음. 수동 최대8묶음/초, 비교 기준2묶음/초.
- M=1/2/3 중 최고 단계만. 같은 묶음의 첫타격에 사망한 적은 남은 타격 무효. 자동ON은현재커서에10~30묶음/초, 수동기본피해 중복 없음. 직접 파훼는 가능.
- 일반·보스60초. 0이 되기 전 유효한 사건만 처리하며 정확히만료시각은만료우선. 보스HP0이면즉시정지 후0.6초처치연출. 생존일반적은0초에보상없이제거.
- 일반은 사망 즉시 런 보상기록, 정상·중도종료에서지급. 보스는처치성공만기본+예약보너스지급,시간초과·포기모두0. 보유잔액을패널티로빼지않는다.
- 실측DPS=실제HP감소/정지를뺀전투시간,과잉피해제외·스킬포함·0초면0. 보스시간차감을분모에더하지않는다.

### 멈춤과 복귀

ESC·창포커스상실·Overlay에서전투/파훼/스킬/타이머를같이멈춘다. ‘계속’을눌러야재개한다. 설정·기록·트리에서는전투를실행하지않는다. 설정의진입화면을보존하고적용/취소뒤원래화면으로돌아간다.

## A06. 저장 · Steam · 지원 기준

진행 저장은 schemaVersion, saveId, 완료L·부분q, 재화5종, 노드 구매, 보스 해금, 엔딩·기록·미전송 실적, 현재런 체크포인트, 정산ID를 포함한다. 문서상 데이터 계약이며 기존 구현 클래스가 있다는 뜻이 아니다.

### 정합성

구매는 잔액과강화상태를단일트랜잭션으로저장한다. 실패면구매롤백. 정산은메모리에결과를보존하고같은ID로재시도한다. 일반5초체크포인트와정상종료저장,백업3세대,임시기록후교체. 비정상종료는일반마지막체크포인트까지만회수하며보스미완료는0. 저장손상·미지원스키마·디스크오류를구분한다.

### Steam 연결 초안

Cloud에는진행·도전과제큐를동기화하고해상도·창모드등장치설정은제외한다. Auto-Cloud구성을우선검토하고충돌선택은Steam클라이언트의흐름에맡긴다. 게임이두기기의재화를합산하지않는다. Steam미연결이어도로컬저장을사용할수있으며실적전송은재접속후재시도한다.

근거: [Steam Cloud 공식 문서](https://partner.steamgames.com/doc/features/cloud?language=english). 경로·할당량·SDK 연결은 구현 시 결정하고 장치2대 전환/오프라인/복귀를 검증한다.

### 실행·성능·회귀

후보검증장비: 내장그래픽 노트북8GB와 보급형외장GPU PC. 이것은최소사양광고가아니다. 1080p낮음기준60FPS목표,실측후최저사양확정. 1,200적·최대90논리타/초,큰범위스킬동시발동에서프레임95백분위와메모리추이를측정한다.

풀반납뒤대상참조무효화,구독해제,트리화면밖노드가상화,단일흐름피해처리,64비트HP/재화·상한검증이필요하다. 숫자·파편·흡수음을묶어표시하되논리적피해·처치량은보존한다.50회런반복에서메모리가계속증가하지않아야한다.
