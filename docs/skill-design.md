# 자동 스킬 기획서

상태: 토네이도·헤드샷·벼락 코어 구현(헤드샷·벼락은 에디터 해금 시험). 밸런스·강화 구성·공식 필드 범위는 미정

작성일: 2026-10-14

이 문서는 앞으로 만드는 모든 전투 스킬의 설계 기준이다. 기존 파이어볼·라이트닝·프리즈닝·허리케인·메테오·드래곤 브레스·커서 오라의 **스킬 기획과 수치는 폐기**한다. 몬스터·커서 공격의 기존 규칙은 이 문서의 변경 대상이 아니다.

새 스킬을 요청할 때는 [새 자동 스킬 구현 요청서](skill-generator-template.md)의 작성란을 채운다.

## 1. 확정된 공통 규칙

1. 해금된 스킬은 전투 중 자동 발동한다. 커서의 기본 공격 활성 여부나 공격 입력은 스킬 발동 조건이 아니다.
2. 스킬마다 독립적인 쿨타임이 있다. 쿨타임은 전투 시계로 계산하며, 일시정지 중에는 진행하지 않는다.
3. 스킬은 서로 다른 생성 위치, 이동, 피격 조건, 반복 피해, 후속 효과를 가질 수 있다. 커서 위치나 범위를 사용하는 스킬도 자동 발동한다.
4. 스킬 피해는 전투의 공통 피해·처치·보상·DPS 집계 경로를 사용한다. 자동 스킬은 보스의 수동 파훼 입력을 대신하지 않는다.
5. 런 종료·포기·시간 만료 뒤에는 새 스킬을 발동하거나 남은 스킬 오브젝트로 피해를 주지 않는다. 정확히 만료 시각에 도달한 경우 만료를 우선한다.

## 2. 최소 공통 구조

공통 전투 경로는 해금 상태와 현재 `RunId`를 스킬 컨트롤러에 전달하고, 런 시계와 공통 피해 경로를 제공한다. 각 스킬 컨트롤러가 자신의 발동 시각과 활성 효과를 관리한다.

스킬별 컨트롤러는 **무엇을 어디에 생성하고 어떻게 공격하는지** 전부 소유한다. 공통 부모 클래스에 범위·투사체 속도·지속 시간·틱 간격·연쇄 횟수 같은 선택 필드를 계속 추가하지 않는다. 필요한 공통 호출 규약은 작은 인터페이스로 둔다. 두 번째 스킬에서 실제로 공통되는 동작이 확인되기 전까지 범용 행동 그래프나 범용 효과 컴포넌트를 만들지 않는다.

| 공통 실행기·전투 경로 | 스킬별 컨트롤러 |
|---|---|
| 해금 확인, 런 시계 | 독립 쿨타임, 발동 조건과 생성 위치 |
| 일시정지, 만료, 런 종료 및 `RunId` 확인 | 오브젝트 개수, 이동, 수명, 타격 주기 |
| 피해·처치·보상·DPS 집계 호출 | 고유 연출, 후속 효과, 스킬별 수치 적용 |

스킬별 쿨타임이 준비되었지만 발동할 대상이 없을 때 소비할지 여부는 **해당 스킬이 정의**한다. 토네이도처럼 대상 없이 생성되는 스킬은 예정대로 발동한다. 한 프레임이 길어져 여러 발동 시각을 지났더라도 밀린 발동을 한 프레임에 몰아서 실행하지 않는다.

## 3. 프리팹과 밸런스 편집

모든 스킬 컨트롤러와 월드에 생성되는 스킬 오브젝트는 프로젝트 소유 프리팹으로 만든다. **컨트롤러 프리팹 인스턴스를 Main 씬의 `CombatManager` 아래에 스킬마다 하나씩 배치한다.** 실제 플레이의 기본 쿨타임·전투 수치는 이 씬 오브젝트의 Inspector에서 조정한다. 프리팹 에셋은 새 씬에 배치할 때의 기본값과 오브젝트 프리팹 참조를 제공한다.

**컨트롤러에서 조절 가능한 값과 특성 업그레이드 대상은 별개다.** 각 스킬 컨트롤러에는 밸런스와 연출에 필요한 수치를 폭넓게 노출한다. 그중 플레이어가 강화할 수 있는 항목은 스킬마다 기획에서 선택한 값만 사용한다. Inspector에 새 수치를 추가했다고 특성 업그레이드 항목이 자동으로 늘어나지 않는다. 강화 대상이 아닌 값은 컨트롤러의 설정값으로 적용하며, 나중에 강화 대상으로 삼으려면 해당 스킬의 강화 규칙·성장 노드·런 스냅샷 연결을 명시적으로 추가한다.

```text
Combat/Prefabs/Skills/TornadoSkillController.prefab
  TornadoSkillController: 기본 수치, 발동 및 오브젝트 프리팹 참조

Combat/Prefabs/Skills/TornadoObject.prefab
  TornadoObject: 수명·피격 동작
  Visual: FX_SnowTornado_Loop 중첩 프리팹 또는 Variant
  HitArea: 연출과 분리된 투명한 트리거 BoxCollider2D
```

토네이도에 사용할 연출은 `Assets/DownLoadAssets/Eric VFX Studio/Game VFX - Tornado Collection/Prefab/URP/FX_SnowTornado_Loop.prefab`이다. 공급사 원본은 수정하지 않는다. 오브젝트 프리팹의 위치·크기·파티클·머티리얼·정렬은 나중에 후보정할 수 있어야 하며, 시각 효과의 실제 파티클 충돌에 피해 판정을 의존하지 않는다. 해당 원본은 파티클 오브젝트로 구성되어 있으므로 몬스터에 대한 논리적 피격 판정은 게임 전용 오브젝트에서 제공한다.

**실제 플레이의 전투 기본 수치 편집 위치는 Main 씬의 각 스킬 컨트롤러 인스턴스**다. Inspector 변경은 씬 프리팹 override로 보존한다. 현재 성장 데이터는 토네이도 해금만 보유한다. 어떤 특성과 수치를 강화할지는 코어를 조정한 뒤 정한다. 그때 선택한 항목에 한해 성장 노드·런 스냅샷·컨트롤러 계산을 연결한다. Inspector에 새 수치를 추가했다고 업그레이드 항목이 자동으로 늘어나지 않는다. 런 중에는 직렬화된 기본값을 덮어쓰지 않는다. JSON과 `SkillCombatSnapshot`에는 스킬 기본 피해·범위·쿨타임을 중복 저장하지 않는다.

토네이도 컨트롤러의 `Editor Play Mode test`에서 `Skill Acquired`를 켜면 구매하지 않은 토네이도도 다음 전투에서 발동한다. 이를 끄면 저장된 해금 상태를 따른다. 이 토글은 Unity 에디터 플레이에서만 적용된다. 개수·지속 시간·공격력·쿨타임 등은 컨트롤러의 기본 수치를 직접 조절해 시험한다.

## 4. 풀링과 성능 규칙

- 월드 스킬 오브젝트와 반복 사용되는 VFX는 스킬별 풀에서 꺼내고 반환한다. 발동이나 매 타격마다 `Instantiate`/`Destroy`하지 않는다.
- 지속 오브젝트를 쓰는 스킬은 예상 동시 개수·지속 시간·쿨타임을 보고 프리워밍 수와 활성 상한을 정한다. 16개는 현재 토네이도 프리팹의 임시 안전 상한일 뿐, 다른 스킬에 복사할 공통 수치가 아니다. 상한 초과 시의 정책은 스킬별로 정하되 무제한 생성하지 않는다.
- 재사용 전 위치, 수명, 타격 시계, 이미 맞힌 대상 기록, 파티클·트레일·오디오 상태를 초기화한다. 반환 시 충돌·이벤트 구독을 끊고 오래된 대상 참조를 지운다.
- 각 오브젝트는 생성된 `RunId`를 보관한다. 풀 반환 뒤의 지연 콜백이나 이전 런의 효과는 현재 런을 공격하지 못한다. 런 종료 시 활성 오브젝트를 모두 반환한다.
- 범위 검색은 재사용 버퍼를 쓰고, 다중 콜라이더를 가진 적은 같은 타격에서 한 번만 처리한다. 버퍼 용량을 넘겼을 때 조용히 적을 누락하지 않도록 계측한다.
- 논리적 피해 횟수와 보상은 유지하되, 숫자·파티클·소리는 화면 밀도에 따라 묶거나 생략할 수 있다. 프로파일링에서는 할당량, 활성 오브젝트 상한, 프레임 시간, 반복 런 뒤 풀 크기를 확인한다.

## 5. 새 스킬 구현 파이프라인

토네이도에서 재사용할 흐름은 **해금 정보 → Main 씬의 스킬 컨트롤러 → 독립 발동 시계 → 스킬 고유 효과와 판정 → 공통 피해 처리 → 효과 종료와 재사용**이다. 토네이도의 무작위 생성, 이동 방식, 박스 히트 영역, 반복 타격 수치는 이 흐름의 공통 요구사항이 아니다. 아래는 앞으로 스킬을 추가할 때 따를 작업 순서이며, 자동 등록 시스템이 이미 구현됐다는 뜻은 아니다.

### 5.1 구현 전에 스킬별로 결정할 것

| 항목 | 기획에서 정할 질문 |
|---|---|
| 발동 | 첫 발동 시점과 독립 쿨타임은? 적이 없어도 발동하고 쿨타임을 소비하는가? |
| 기준 위치 | 필드 무작위 위치, 현재 커서, 특정 적, 고정 지점 중 어디를 쓰는가? 좌표나 범위의 출처는? |
| 공격 과정 | 직접 피해, 투사체, 이동 영역, 영역 진입 후 후속 효과 중 무엇인가? 대상은 언제 확정하는가? |
| 타격 | 최초 타격 시점, 반복 간격, 한 대상의 재타격 조건, 여러 효과가 겹칠 때의 피해 규칙은? |
| 수명 | 효과 지속 시간과 종료 연출은? 일시정지·런 종료·대상 소멸 시 무엇을 반환하는가? |
| 제작물 | 컨트롤러 외에 월드 오브젝트, 히트 영역, 별도 피해 연출 중 무엇이 필요한가? |
| 예산 | 예상 동시 오브젝트 수와 상한, 풀 부족 또는 검색 버퍼 부족 시의 정책은? |

공식 필드 범위와 경계 처리 방식은 아직 정하지 않는다. 필드 위치를 쓰는 새 스킬은 현재 필요한 좌표 기준을 해당 스킬 기획에 적고, 토네이도의 임시 카메라 패딩 값을 공통 규칙으로 옮기지 않는다. 강화 항목과 단계 수치도 코어 플레이를 확인한 뒤 별도로 결정한다.

### 5.2 데이터에서 전투까지 연결하는 순서

1. **고정 ID와 해금 데이터:** `game-data.en.json`의 스킬 정보, `progression-config.en.json`의 해금 노드, 표시 정보에 같은 `skill.*` ID를 쓴다. 구매·저장은 Progression이 소유한다. 런 시작 정보의 `SkillCombatSnapshot(SkillId, Unlocked)` 목록은 App을 거쳐 Combat에 전달한다. 스킬별 전투 기본 수치는 성장 JSON에 복제하지 않는다.
2. **현재의 단일 스킬 가정 해제:** 다음 스킬을 추가할 때 `GameInformation`의 스킬 수·ID 검사, `GameDataDocument`의 토네이도 전용 검증, Python 데이터 검사·예제·테스트의 스킬 수 1개 가정을 함께 수정한다. 한쪽만 늘려서 해금은 보이지만 전투에서 누락되는 상태를 만들지 않는다.
3. **컨트롤러 프리팹과 씬 배치:** 스킬마다 독립 컨트롤러 프리팹을 만들고 Main의 `CombatManager` 아래에 인스턴스를 하나 배치한다. Inspector에는 실제 기본 수치와 필요한 참조를 노출한다. 에디터의 획득 시험 토글은 저장된 해금 상태를 영구 변경하지 않는다. Sandbox에도 같은 컨트롤러 프리팹을 놓고 고정 런 스냅샷으로 검증한다.
4. **필요한 효과만 제작:** 월드 오브젝트가 있으면 프로젝트 소유 루트 프리팹 아래에 원본 VFX를 자식이나 Variant로 넣는다. 시각 효과와 논리적 판정을 분리하고, 해당 스킬에 필요한 히트 영역만 만든다. 직접 타격처럼 지속 오브젝트가 없는 스킬에는 빈 오브젝트나 토네이도식 풀을 억지로 만들지 않는다.
5. **런 수명주기 연결:** 현재 `CombatRunController.ConfigureSkills`와 종료 처리는 토네이도 전용이다. 두 번째 스킬을 연결할 때 ID별 해금 판정, 시작, 종료만 공유하는 작은 실행 규약 또는 등록 목록으로 전환한다. 공통 부모에 토네이도의 이동·수명·범위 필드를 넣지 않는다. 각 컨트롤러는 전달받은 런 정보로 자신의 시계와 효과를 관리한다.
6. **공통 피해 경로 사용:** 스킬은 현재 런의 공격 가능한 대상을 확인하고 `CombatRunController.TryApplySkillDamage`로 피해를 전달한다. 체력 감소, 치명타, 처치, 보상, DPS를 스킬에서 별도로 계산하지 않는다. 여러 콜라이더를 가진 한 적의 중복 타격과 여러 효과의 중첩 규칙은 스킬 기획대로 처리한다.

### 5.3 실행·성능·검증 기준

- 커서 공격을 하지 않아도 해금된 스킬의 발동 시계가 진행되어야 한다. 일시정지에서는 시계·효과·타격이 멈추고, 시간 만료와 런 종료 뒤에는 이전 `RunId`의 피해가 발생하지 않아야 한다.
- 재사용하는 오브젝트와 VFX는 시작·반환 때 위치, 크기, 파티클, 타격 시계, 대상 기록을 초기화한다. 발동마다 생성이 필요한지, 풀을 미리 채우는 순간에 끊김이 없는지 예상 동시 개수로 확인한다.
- 타격 루프는 재사용 버퍼를 우선한다. 후보 콜라이더 수가 버퍼를 넘으면 실제 대상이 빠지는지 확인하고, 풀이나 검색 상한이 전투 수치를 몰래 낮추지 않도록 정책을 정한다. 물리 조회·파티클·프레임 할당은 대표적인 몬스터 밀도에서 측정한다.
- Sandbox에서는 해금/잠금, 쿨타임, 반복·중첩 피해, 일시정지, 만료, 재시작, 풀 재사용을 검증한다. Main에서는 실제 획득 상태와 Inspector 기본 수치, 커서 공격 비활성, 일반전·보스전 연동을 확인한다. 해당 스킬의 생성 위치와 타격 방식은 강제로 겹치게 만든 테스트 외에 자연스러운 플레이에서도 확인한다.

## 6. 첫 스킬: 토네이도

**확정:** 토네이도는 커서 공격과 관계없이 쿨타임마다 필드의 무작위 위치에 생성된다. 일반전과 보스전 모두 같은 무작위 위치 규칙을 사용한다. 여러 개를 생성하는 발동은 하나의 스킬 쿨타임을 공유하고, 각 오브젝트는 별도 위치와 수명을 가진다.

현재 토네이도 특성 업그레이드는 없다. 개수, 지속 시간, 공격력, 재사용 대기시간, 이동 속도, 방향 변경 주기, 정지 확률·시간, 타격 간격, 소멸 축소 시간, 생성 영역, 히트박스 크기는 Inspector나 전용 프리팹에서 조절한다. 강화 항목과 단계별 수치는 추후 코어를 시험한 뒤 결정한다.

각 토네이도는 컨트롤러에 설정된 이동 속도로 움직인다. **3초마다 무작위로 이동 경로를 바꾸며, 일부 구간에는 잠시 정지한다.** 적을 추적하지 않는다. `TornadoObject`의 투명한 `HitArea` 트리거 박스 안의 적은 일정 간격으로 반복 타격한다. 같은 적이 여러 토네이도와 겹치면 **각 토네이도가 독립적으로 피해를 준다.**

이동 속도는 Main 씬의 `TornadoSkillController`에서 조절하며 에디터 플레이 중 변경하면 활성 토네이도에도 바로 적용한다. 수명이 끝나기 전 마지막 1초 동안 토네이도 루트와 히트박스가 함께 점차 작아진다. `Shrink Out Seconds`는 컨트롤러에서 조절할 수 있고 0이면 축소 연출을 끈다. 풀에 반환하면 원래 크기로 복원한다.

아래 수치는 첫 플레이테스트용 **임시 제안**이며 확정되지 않았다.

| 항목 | 임시 기본값 |
|---|---:|
| 첫 발동 | 런 시작 1초 후 |
| 쿨타임 | 8초 |
| 토네이도 개수 | 1개 |
| 토네이도 공격력 | 타격당 기본 공격력 `A`의 2배 |
| 토네이도 지속 시간 | 5초 |
| 소멸 축소 시간 | 마지막 1초 |
| 타격 주기 | 생성 직후, 이후 0.5초마다 |
| 피격 영역 | 3 × 3 월드 단위 트리거 박스 |
| 이동 속도 | 초당 1 월드 단위 |
| 방향 변경 주기 | 3초 |
| 정지 확률·시간 | 방향 변경 시 25%, 0.75초 |

기본 공격력 `A`는 런 시작 시의 공격력이다. 타격마다 전투의 치명타 판정을 받고, 보스전에는 보스 피해 배율을 적용한다. Main의 토네이도 컨트롤러 풀 상한 16개는 현재의 임시 안전 장치이며, 토네이도를 16개 생성한다는 기획은 아니다.

토네이도는 필드의 무작위 위치에 생성하며 적의 위치를 목표로 삼지 않는다. 적이 없어도 생성하고, 여러 개를 설정하면 각각 위치를 뽑는다. 현재 구현은 카메라 뷰포트와 임시 패딩 값으로 위치를 계산한다. 공식 필드 범위와 경계 처리 기준은 추후 정한다.

### 몬스터 타격 흐름

쿨타임이 되면 활성 토네이도 수가 상한 이내인지 확인하고, 필요한 오브젝트를 풀에서 꺼내 각각의 무작위 위치에 배치한다. 오브젝트는 런 시계에 따라 살아 있는 동안 자기 범위의 몬스터를 검사한다. 같은 몬스터의 여러 콜라이더는 한 번의 타격으로 묶고, 현재 `RunId`에 속하며 공격 가능한 대상에만 피해를 전달한다. 실제 체력 감소, 처치, 보상, 피해량 표시는 전투의 기존 공통 경로가 처리한다. 수명이 끝나거나 런이 종료되면 오브젝트를 초기화해 풀에 반환한다.

범위 안의 적은 토네이도마다 독립적인 타격 시계에 따라 반복해서 맞는다. 한 토네이도 안에서 같은 적의 여러 콜라이더가 피해를 중복시키지 않으며, 서로 다른 토네이도의 피해는 합산한다. 원본 파티클의 충돌이나 재생 프레임이 논리적 타격 시점을 결정하지 않는다.

### 후보정 시 결정할 항목

- 이동 속도·정지 확률·피격 박스 크기 등 현재 임시 수치의 최종 밸런스
- 이펙트 크기·정렬·피격 순간의 추가 연출과 소리
- 플레이 화면과 보스전에서 허용할 동시 토네이도 밀도

## 7. 토네이도 구현 및 검증 기준

Main에서는 `CombatManager/TornadoSkillController`를 선택해 수치를 조정하고 실제 해금 상태로 플레이한다. 자동 커서 공격을 끈 상태에서도 발동해야 한다. 기존 `CombatSandbox`는 고정 런 스냅샷을 쓰는 자동화 검증용으로 유지한다. 일시정지에서는 쿨타임·수명·타격이 함께 멈춰야 한다. 런 종료, 재시작, 풀 재사용 뒤 이전 런의 피해·중복 보상·남은 연출이 없어야 한다. 씬 컨트롤러의 Inspector 수치 변경은 다음 런의 적용 수치에 반영되어야 한다.

구현 전후에는 [모듈 소유권](collaboration/architecture.md), [런 계약](collaboration/contracts.md), [에셋 사용 규칙](collaboration/assets.md)을 함께 갱신·확인한다. 이 문서의 토네이도 수치가 확정되기 전에는 기존 스킬 JSON의 값이나 이전 스킬 기획을 새 토네이도의 밸런스 근거로 사용하지 않는다.

## 8. 헤드샷 코어 구현

`skill.headshot`은 전투 시작 1초 후부터 준비되고, 적이 없으면 준비 상태를 유지한다. 발동 시 현재 런의 공격 가능한 적 한 명을 무작위로 지목한다. 이펙트는 폭발 전까지 대상을 따라가고, 대상이 사라지면 마지막 위치에 남는다. 기본 폭발 지연은 1.15초이며, 그 순간 주 대상에게 일반전에서는 남은 체력만큼, 보스전에서는 기본 공격력의 10배를 원시 피해로 보낸다. 주 대상의 무적·피해 감소와 전투 공통 치명타·보스 배율은 그대로 적용한다. `HitBox`의 다른 적은 기본 공격력의 2배를 한 번씩 받고, 주 대상은 주변 피해를 중복해서 받지 않는다. 쿨타임 5초와 피해 배율은 첫 시험용 값이다.

전용 컨트롤러와 풀링 효과 프리팹을 Main의 `CombatManager` 및 CombatSandbox에 배치했다. 원본 `FX_Aim_Explode_Visual`의 크기는 유지하고, 프로젝트 소유 효과 프리팹에서 `HitBox`를 조절한다. 에디터의 `Skill Acquired` 토글로 저장을 바꾸지 않고 시험한다. 실제 구매 해금 노드와 특성 업그레이드는 아직 연결하지 않았다. 현재 GameInformation의 스킬 데이터는 토네이도 한 종류를 유지한다. 보스 피해는 합성 보스 런으로 검증했으며, 실제 보스 전투 연결은 보스 런 구현 시 확인한다.

## 9. 벼락 코어 구현

`skill.thunder`는 전투 시작 즉시 준비되며, 적이 없으면 쿨타임을 소비하지 않고 대기한다. 발동할 때 공격 가능한 적 한 명을 무작위로 지목한다. 전용 `ThunderEffect` 루트는 시각 자식의 `HitPoint`를 몬스터 스프라이트 영역의 중심에 맞추며 타격 전까지 대상을 따라간다. 대상이 먼저 죽거나 사라지면 마지막 위치에 남아 연출만 마친다. 다른 적으로 재지목하거나 범위 피해를 주지 않는다. 타격 순간까지 대상이 살아 있으면 기본 공격력의 4배를 한 번 공통 피해 경로로 전달한다. 일반전과 보스전은 같은 기본 수치를 사용하며 전투의 공통 보스 배율은 그대로 적용한다.

컨트롤러 기본값은 쿨타임 2초, 첫 발동 지연 0초, 타격 지연 0.1초, 효과 지속 0.5초다. 모두 Main의 `ThunderSkillController` Inspector에서 조절한다. 반복 재생으로 설정된 공급사 원본 `FX_Cartoon Thunder_Visual`은 프로젝트 소유 `ThunderEffect`의 시각 자식으로만 사용하고, 런타임 인스턴스에서 일회 재생·일시정지·반환을 관리한다. 원본의 파티클과 콜라이더는 피해 판정에 관여하지 않는다. 효과 종료 시 추가 소멸 연출 없이 풀에 반환한다. 수치와 시각적 타격 타이밍은 플레이 화면에서 확인 후 조정할 임시값이다. 에디터 `Skill Acquired` 토글로 시험하며 구매 해금·강화는 아직 연결하지 않았다.
