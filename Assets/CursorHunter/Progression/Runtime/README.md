# Progression/Runtime
담당: 준영 (Contracts는 공동 검토).
용도와 연결 규칙: 프로젝트 루트 docs/collaboration/architecture.md 및 contracts.md.
씬·프리팹·데이터 인스턴스는 담당자가 Unity 6000.3.13f1에서 생성한다.

## Runtime trait screen

`TraitScreenController`는 `Main.unity`의 특성 화면 표시와 입력을 담당한다. 게임 데이터와
진행 설정 JSON의 모든 Stat·Skill·Monster 노드를 하나의 전체 화면 연구 보드에 섞어 표시한다.
펫도 같은 보드에 들어가며, 전투 데이터의 `skill.cursorAura` ID와 저장 호환성은 유지한다.

신규 진행도와 전체 초기화는 `stat.attack.01` 중앙 시작점만 구매 가능하게 둔다. 시작점을
해금하면 동서남북의 기본 스탯 선택지가 열리고, 각 분기는 설정 JSON의 선행 조건을 따라간다.
보드 중앙의 `stat.attack.01` 시작 코어에서 네 방향의 기본 스탯으로 뻗고, 그 바깥으로
선행 조건과 재화 티어, 비용이 낮은 순서대로 확장한다. 모든 연결선은 정사각 그리드의
동서남북 방향만 사용한다. 마우스 휠로 확대·축소하고 드래그로 이동하며, 드래그 중에는
손바닥 커서를 표시한다. 화면 오른쪽 위의 줌 버튼은 제공하지 않는다.
화면은 캔버스 전체를 사용하며 상단 HUD는 그래프 영역을 줄이지 않는다.

노드를 클릭하면 말풍선을 고정해 설명·수치·비용·보유 재화·선행 조건·해금/강화 상태를
확인하고 바로 구매하거나 초기화할 수 있다. 구매 가능한 노드의 버튼에는 스킬/몬스터 해금
또는 강화 동작을 구체적으로 표시하고, 구매 완료·재화 부족·선행 잠금도 버튼에서 구분한다.
툴팁의 구매 버튼은 카드 안쪽에 배치한다. 화면을 다시 열면 111개 전체 보드가 화면에 맞게
축소되고, 확대·축소 하한은 전체 지도를 확인할 수 있도록 둔다. 구매 뒤 새로 열린 다음 노드는 상태 테두리와
펄스 이펙트로 강조한다. 테두리는 강화 완료(청록), 구매 가능(금색), 재화 부족(주홍),
잠김(자홍)으로 구분한다. 호버 시 노드를 확대하고 구매 시 노드에 사각 펄스와 파편을 재생한다.

우측 상단 테스트 도구에서 임의 수량의 젬스톤을 종류별 또는 전체 지급하고, 모든 잠금 조건을
테스트용으로 해제하거나 전체 노드를 해금·강화할 수 있다. 테스트 구매는 저장되며 화면 하단의
전체 초기화는 비용을 환불하고 중앙 시작점만 구매 가능 상태로 되돌린다. 상단에는 통합 연구 탭과 기획용 유물 자리만 둔다.
유물 탭은 시각적 자리 표시자이며 기능은 아직 연결하지 않았다.

전체 정보 팝업은 게임 정보와 모든 연구 노드의 상태·비용·선행 조건을 한국어로 표시한다.
전투 정보 JSON과 전체 게임·연구 설정 JSON을 영문 키 그대로 각각 복사할 수 있다.

배경에는 기존 `field_a.png` 타일과 Main 씬의 신석기 전장을 사용하고, 짙은 남색 셰이드로
대비를 맞춘다. 원본 타일을 확대 저장하지 않고 `Image.Type.Tiled`로 반복한다.

`TraitTab` enum과 `ShowStatTab` 등의 공개 진입점은 기존 App 바인딩 호환을 위해 남겨 둔다.
런타임 보드의 통계·스킬·몬스터 분기는 합친 채 유지하며, 상단의 유물 자리는 추후 기획을 위한
비활성 표시로 둔다.
한국어 표시에는 프로젝트 동적 SDF 폰트를 사용한다. 노드 구매는 `CostGemstoneId`에
따라 잔액에서 차감하고 초기화할 때 환불한다. 구매 상태와 젬 잔액은
`TraitProgressionStore`의 PlayerPrefs JSON에 저장한다. 런 시작 시
`CreateCombatSnapshot()`이 최종 정보와 커서 보너스를 값 복사하고, App은 Eligible `RunResult.Rewards`를
`GrantResourceRewards()`로 한 번 반영한다. Combat은 이 컴포넌트나 저장소를 직접
참조하지 않는다. 출시 전 PlayerPrefs를 정식 파일/클라우드 저장으로 교체한다.

Main 씬에서는 App이 `PlayerCombatStatsDefaults`의 공통 커서 기본값 스냅샷을 전달한다.
`GameInformationBuilder`는 기본값에 보유 특성의 `add` 델타를 합산해 전체 정보와 요약을
만들고, `CreateCursorCombatStatBonusesSnapshot()`은 같은 델타만 별도 계약으로 반환한다.
공격력·반경·쿨다운·치명타·보스 피해 노드의 값은 최종값이 아니라 증가량이다.
쿨다운 감소는 음수 델타로 표현하며 최종 쿨다운은 0.05초 이상, 치명타 확률은 100% 이하로 제한한다.
스킬 특성은 현재 배율 방식을 유지하고, 설정된 공격력-스킬 피해 연동은 기본 공격력 대비 비율로 계산한다.


## 현재 런타임 데이터 기준

진행 설정 JSON이 성장 비용·효과·선행 조건의 원본이다. 현재 통합 보드는 Stat 43개,
스킬 24개와 펫 4개, 몬스터 해금·생산 40개를 합친 111개 노드를 표시한다. 노드 ID와 JSON의
`skills` 소유권은 구매 저장 및 전투 호환성을 위해 그대로 둔다.

- `TraitTab` 값은 `Stat=0`, `Skill=1`, `Monster=2`다.
- `Main.unity`의 `petIcon`/`petIcons[0]`은 통합 연구 보드의 펫 동료 노드에 사용한다.
- 젬스톤 표시명과 잔액은 상단 HUD로 보여 주고, 노드별 효과·비용은 클릭으로 고정되는 말풍선에서 확인한다.
- 마우스 휠 확대, 드래그 이동·손바닥 커서, 임의 젬 지급, 전체 조건 해제·전체 강화 테스트 도구를 제공한다.
- 전체 정보 팝업은 한국어로 렌더링하며, 전투 정보와 전체 진행 설정 JSON 복사를 제공한다.
- 몬스터 기본 밸런스는 `TraitMonsterBalanceDefinition`에서 관리한다.
